## 요구사항

### 기능 요구사항

- **FR-1.** 설정 화면이 **탭 넷**으로 갈린다 — `실행` · `앱` · `repo` · `정보`. 지금처럼
  사이드바 하단에서 열고 닫으며, 모달이 아니라 본문 영역을 대신 차지한다(전체 설계 §509).
- **FR-2.** 탭은 **어느 범위의 값인지로 가른다.** `실행`과 `repo`는 지금 고른 workspace에
  걸리고, `앱`은 장비 전체에 걸린다. 화면이 그 구분을 문장으로 알려준다.
- **FR-3.** `실행` 탭에서 workspace 기본값을 바꾼다 — 기본 agent, 기본 모델(claude용과
  opencode용 **각각**), 기본 권한, claude·opencode 실행 파일 경로.
- **FR-4.** 기본 모델은 agent별로 따로 입력한다. 두 CLI의 모델 지정 형식이 다르기 때문이다
  (전체 설계 §199 — claude는 `sonnet` 같은 별칭, opencode는 `provider/model`).
- **FR-5.** 실행 파일 경로를 **비우면 자동 탐색으로 돌아간다**(`core/runner/agentPath.ts`가
  `null`일 때 하는 일). 화면이 그렇게 안내한다.
- **FR-6.** 기본 권한을 **전체 허용으로 올릴 때만** 확인을 한 번 더 받는다. 확인하기 전에는
  값이 바뀌지 않는다(전체 설계 §403). 낮추는 방향은 확인하지 않는다.
- **FR-7.** `앱` 탭에 글로벌 asset 경로(claude용·opencode용)와 동시 실행 상한을 둔다.
  **상한은 도크의 슬롯 표시기에도 그대로 남는다** — 한쪽에서 바꾸면 다른 쪽이 즉시 따라온다.
- **FR-8.** `repo` 탭에서 등록된 repo의 **경로**·이름·설명을 고친다. 지금은 경로 편집이
  앱에 없어 `docs/windows-setup.md` §4가 SQL을 안내한다.
- **FR-9.** repo 경로를 바꾸면 그 repo의 asset 행의 `file_path`를 **새 경로로 옮기고**
  곧바로 다시 훑는다. 행을 새로 만들지 않는다 — 과거 run이 첨부한 asset의 기록이 id로
  이어져 있기 때문이다(전체 설계 §232).
- **FR-10.** `정보` 탭은 읽기 전용으로 MCP 서버 상태와 포트, DB 파일 경로, 로그 디렉토리,
  앱 버전을 보여준다. 여기에 **정해진 두 위치(데이터·로그)를 파일 탐색기로 여는 버튼**만
  붙는다.
- **FR-11.** 값은 **필드 단위로 커밋된다** — Enter 또는 포커스를 잃으면 저장, Esc는 취소.
  앱에 이미 있는 패턴이다(`RenameField.tsx`, `SlotIndicator.tsx`). **저장 버튼이 없으므로
  "저장하지 않은 상태"라는 것이 존재하지 않고, 탭을 옮겨도 잃을 것이 없다.**
- **FR-12.** 저장이 실패하면 그 필드 옆에 이유를 보여주고 **입력한 값을 지우지 않는다.**
- **FR-13.** workspace를 고르지 않은 상태에서 `실행`·`repo` 탭을 열면 고르라고 안내한다.
  `앱`·`정보` 탭은 workspace 없이도 동작한다.

### 비기능 요구사항

- **NFR-1.** 마이그레이션이 없다. 필요한 컬럼(`workspace.default_*`, `*_path`, `repo.path`)과
  `app_setting` 키가 이미 전부 있다.
- **NFR-2.** 경계 셋을 지킨다. `core/`는 `electron`을 import하지 않고(앱 버전·경로 열기는
  main이 처리한다), `renderer/`는 `core/`를 import하지 않으며, IPC 핸들러는 얇다.
- **NFR-3.** 렌더러가 **임의의 경로를 열어달라고 할 수 없다.** 여는 대상은 `'data' | 'logs'`
  같은 정해진 값으로만 지정한다 — `repos.openInEditor`가 경로 대신 id를 받는 것과 같은 이유다.
- **NFR-4.** 경로·모델 문자열은 화면에 **평문으로** 그린다. 사용자와 파일시스템에서 온
  값이지 신뢰된 마크업이 아니다.
- **NFR-5.** 설정 화면이 실행 중인 run에 영향을 주지 않는다. 기본값은 **다음 실행부터**
  적용되고, 상한 변경만 즉시 큐에 반영된다(`queue.setLimit`이 이미 그렇게 동작한다).
- **NFR-6.** 새 런타임 의존성을 더하지 않는다.
- **NFR-7.** 배선을 테스트가 고정한다. `App.tsx`가 자식에게 내려보내는 prop 한 줄이 3a·3b
  리뷰에서 반복해 새어나간 자리다(CLAUDE.md).

## 범위 밖

- **workspace 만들기·이름 바꾸기·지우기.** 사이드바에 있고 그대로 둔다.
- **repo 등록·삭제.** `AddRepoForm`과 기존 자리를 그대로 둔다. 이번에는 이미 등록된 것의
  값을 고치는 것만 다룬다.
- **테마·글꼴·단축키.** 설정에 담을 만하지만 지금 그런 값이 없다.
- **API 키·자격 증명.** claude와 opencode가 각자 관리한다. 앱이 손에 쥐지 않는 것이 현재
  구조의 이점이다(CLAUDE.md의 환경변수 절).
- **설정 내보내기·가져오기.** 장비 이관은 DB 파일 복사로 한다(`docs/windows-setup.md` §4).
- **기본 모델을 실행 패널이 읽게 하는 배선.** task_926353a6가 먼저 병합된다(아래
  "확인 필요 항목"에서 해소). 이 작업은 그 값을 **고치는 화면**만 만든다.

## 설계

### 개요

셋이 함께 움직인다.

**1) 화면은 탭 컨테이너가 된다.** `SettingsPanel.tsx`가 지금은 글로벌 경로 두 칸을 직접
그린다. 이것을 탭 넷을 가진 껍데기로 바꾸고, 지금 내용은 `앱` 탭으로 내려간다. 탭 상태는
컴포넌트 안에만 있다 — 화면 전환은 이미 `App.tsx:25`의 `view`가 하고 있고 거기에 탭까지
얹으면 두 곳이 같은 것을 관리하게 된다.

**2) 쓰기 통로가 열린다.** 지금 IPC에는 workspace의 이름을 바꾸는 `rename`과 repo의 이름을
바꾸는 `rename`만 있다(`shared/client.ts:19-38`). 둘 다 "다른 필드는 건드리지 않는다"고
주석에 못 박혀 있다. 여기에 기본값과 경로를 고치는 갱신 통로를 더한다. **핸들러는 얇게
유지하고 검증은 core에 둔다** — 권한 값의 유효성, 상한의 범위, repo 경로의 존재 여부가
전부 core의 판단이다.

**3) repo 경로 변경은 asset을 데리고 간다.** 경로를 바꾸면 그 아래 asset의 `file_path`가
전부 달라진다. 동일성 키가 `(workspace_id, file_path)`이므로 아무것도 하지 않으면 **옛
행이 "없음"으로 남고 새 행이 쌓여 목록이 조용히 두 배가 된다.** 그래서 경로 갱신과
`file_path` 접두사 치환을 **한 트랜잭션**으로 처리하고, 끝난 뒤 그 workspace를 다시 훑는다.

### 데이터 모델

**스키마 변경 없음.** 쓰는 자리는 이미 있다.

| 값 | 저장 위치 | 범위 | 비우면 |
|---|---|---|---|
| 기본 agent | `workspace.default_agent_kind` | workspace | 비울 수 없다(NOT NULL, 기본 `claude-code`) |
| 기본 모델 | `workspace.default_model_claude` · `default_model_opencode` | workspace | CLI 자신의 기본값 |
| 기본 권한 | `workspace.default_permission` | workspace | 비울 수 없다(NOT NULL, 기본 `edit`) |
| 실행 파일 경로 | `workspace.claude_path` · `opencode_path` | workspace | 자동 탐색 |
| 글로벌 asset 경로 | `app_setting['assets.globalRoots.*']` | 장비 | 기본 경로로 되돌아간다 |
| 동시 실행 상한 | `app_setting['run.concurrencyLimit']` | 장비 | 비울 수 없다(기본 3) |
| repo 경로·이름·설명 | `repo.path` · `name` · `description` | workspace | 경로는 비울 수 없다 |

`workspace.updated_at`은 갱신할 때 함께 올린다. 시각은 epoch milliseconds 정수를
`Date.now()`로 명시 삽입한다(CLAUDE.md 데이터 규칙).

**낙관적 잠금을 쓰지 않는다.** 이슈·메모 본문과 달리 설정은 agent가 MCP로 고치지 않고
사람이 한 화면에서만 고친다. 마지막 쓰기가 이긴다.

### 인터페이스

**core** — 새 메서드 셋.

- `workspaces.updateDefaults(id, patch)` — 기본 agent·모델 둘·권한·실행 파일 경로 둘 중
  넘어온 것만 고친다. 권한을 `full`로 올리는 것도 여기서는 그냥 값이다. **확인 절차는
  화면의 몫이지 core의 몫이 아니다** — core는 같은 호출을 테스트에서도 받는다.
- `repos.update(id, patch)` — 이름·설명·경로. 경로가 바뀌면 asset `file_path` 치환과
  재스캔까지 한 호출 안에서 끝낸다.
- `app.info()` — DB 파일 경로, 로그 디렉토리. **버전은 core가 모른다**(package.json은
  main의 것이다).

**IPC** — `shared/channels.ts`에 채널 셋, `shared/client.ts`에 같은 모양의 메서드.
`app:info`는 core의 값에 main이 아는 것(앱 버전)을 합쳐 돌려준다. `app:reveal('data' |
'logs')`는 정해진 두 위치만 연다(NFR-3).

**MCP 상태**는 이미 있다 — `mcpStatus` 채널과 `mcpStatusUpdate` 이벤트, `McpStatus` 타입
(`shared/models.ts:10`). `정보` 탭은 사이드바가 쓰는 것과 같은 것을 읽는다.

**화면** — `SettingsPanel`이 탭 넷을 가지고, 각 탭은 자기 데이터만 읽는다. `실행`·`repo`
탭은 지금 고른 `workspaceId`가 필요하므로 `App.tsx`가 prop으로 내려보낸다(NFR-7이 이 줄을
가리킨다).

### 예외 처리

- **repo 경로가 존재하지 않으면** 저장을 거부하고 이유를 보여준다. 실행의 cwd가 되는
  값이라 존재하지 않는 경로를 넣으면 다음 실행이 실패한다.
- **경로 치환이 유니크 인덱스에 걸리면**(새 경로에 이미 같은 `file_path` 행이 있는 경우)
  트랜잭션을 되돌리고 경로 변경 자체를 실패로 알린다. 같은 repo를 두 번 등록한 상태가
  아니면 일어나지 않는다.
- **실행 파일 경로에 `.cmd`를 넣으면** 저장은 되지만 실행 직전 preflight가 거부한다
  (CLAUDE.md — `.cmd`는 `shell: true` 없이 spawn하면 `EINVAL`이다). 저장 시점에 미리
  같은 검사를 돌려 경고한다.
- **상한을 1 미만이나 정수가 아닌 값으로** 넣으면 setting 저장소가 던진다. 화면은 그
  메시지를 필드 옆에 보여주고 값을 되돌린다.
- **MCP가 `failed` 상태면** `정보` 탭이 그 메시지를 그대로 보여준다. 설정 화면이 서버를
  다시 띄우려 하지 않는다.

## 정책 검토

- **CLAUDE.md의 경계 셋** — 준수한다(NFR-2). 앱 버전과 경로 열기는 main에 둔다.
- **전체 설계 §403** — 기본 권한을 전체 허용으로 바꿀 때의 별도 확인 절차를 FR-6이 구현한다.
- **전체 설계 §199** — 모델 기본값을 agent별로 나눈 이유가 그대로 FR-4다.
- **전체 설계 §232** — 사라진 asset을 지우지 않는다. FR-9가 행을 지우지 않고 옮긴다.
- **헤드리스 권한 규칙** — 설정 화면은 `read_only`·`edit`·`full` 셋만 다룬다. `ask`는
  애초에 값으로 존재하지 않는다(CLAUDE.md).
- **의도된 중복 규칙** — 해당 없음. 이슈·메모 대칭을 건드리지 않는다.
- **데이터 규칙** — 시각은 epoch ms 정수, 쓰기는 트랜잭션(FR-9의 치환이 특히).

- ~~**동시 실행 상한을 두 자리에 두는 것이 옳은가.**~~ → **해소됨(2026-09-19).**
  **양쪽에 둔다** — 도크는 run이 대기하는 맥락 바로 옆이라는 이점이 있고, 설정은 설정대로
  한자리에 모인다. 둘은 같은 `app_setting` 키를 읽고 쓰므로 어긋날 수 없다(FR-7).

  대화의 재개(`claude --resume`)가 다른 디렉토리를 가리키게 된다. 세션은 특정 CLI가 특정
  디렉토리에서 만든 것이라(전체 설계 §362) **경로를 바꾼 뒤 옛 대화를 이어가면 무엇이
  일어나는지 실측되지 않았다.** → Build 전에 확인하거나, 경로 변경 시 경고 문구를 붙인다.
- **`정보` 탭의 "폴더 열기"가 새 통로를 연다.** 정해진 두 위치만 열도록 막았지만(NFR-3),
  파일 탐색기를 띄우는 능력 자체가 지금 앱에 없던 것이다. `repos.openInEditor`가 이미
  VS Code를 띄우므로 전례는 있다. → 이 정도로 충분한지 판단 필요.
- **workspace가 하나뿐이라 범위 구분이 실측되지 않는다.** 이 장비의 DB에는 workspace가
  `focus-yard` 하나다. "workspace를 바꾸면 `실행` 탭의 값이 따라 바뀐다"는 약속은 **둘째
  workspace를 만들어야 검증된다.** → 테스트에서 둘을 만들어 확인한다.
- **즉시 커밋으로 바꾸면 기존 글로벌 경로 UI가 달라진다.** 지금은 저장 버튼이고
  `SettingsPanel.test.tsx`와 `e2e/asset.e2e.ts`가 그 버튼을 누른다. FR-11을 따르면 두
  테스트를 고쳐야 한다 — **테스트가 깨지는 것이 곧 이 변경의 비용이다.**

## intent 미해결 질문에 대한 답

- **탭을 어떻게 가르는가** → 넷으로 가르되 **범위를 기준으로** 가른다(FR-1·FR-2).
  `실행`·`repo`는 workspace, `앱`은 장비, `정보`는 읽기 전용.
- **어느 workspace를 다루는가** → 사이드바에서 고른 것. 고르지 않았으면 안내만 한다(FR-13).
  화면 안에 workspace 선택기를 따로 두지 않는다 — 고르는 자리가 둘이 된다.
- **기본 모델 컬럼을 배선하는가, 지우는가** → **배선한다.** 전체 설계 §199가 "모델 기본값을
  agent별로 나눈 이유"를 명시적으로 설명한다. 설계가 버린 값이 아니라 구현이 빠진 값이다.
- **repo 경로 변경 시 asset을 어떻게 하는가** → `file_path`를 새 경로로 옮기고 재스캔한다
  (FR-9). 행을 새로 만들지 않는다.
- **동시 실행 상한을 즉시 반영하는가** → 이미 즉시 반영된다(`queue.setLimit`). 남은 결정은
  "어디에 두는가"뿐이며 확인 필요 항목으로 올렸다.
- **저장 방식** → 필드 단위 커밋(Enter·blur), 저장 버튼 없음(FR-11). 앱에 이미 있는 패턴을
  따르고, "저장하지 않은 상태"를 만들지 않는 것이 intent의 성공 기준 4를 직접 만족한다.
- **위험한 값의 확인 절차** → `ConfirmButton`의 두 번 누르기 패턴을 쓴다(FR-6). 이름을
  타이핑하는 `DeleteByName`은 되돌릴 수 없는 삭제를 위한 것이라 과하다.
- **진단 탭의 범위** → 읽기 전용 + 정해진 두 위치 열기까지(FR-10·NFR-3).

## 수용 기준

1. 설정 화면을 열면 탭 넷이 보이고, 각 탭이 자기 범위를 문장으로 밝힌다.
2. `실행` 탭에서 기본 agent를 OpenCode로 바꾸면, **SQL 없이** 다음에 연 실행 패널의
   드롭다운이 OpenCode로 열린다.
3. 기본 권한을 전체 허용으로 고르면 한 번 더 확인을 받고, 확인하지 않으면 값이 그대로다.
   낮추는 방향은 확인 없이 바뀐다.
4. 실행 파일 경로를 비우면 자동 탐색으로 돌아가 실행이 정상 동작한다.
5. `repo` 탭에서 경로를 바꾸면 그 repo의 asset이 목록에서 **두 벌로 늘지 않는다.**
6. 존재하지 않는 경로를 넣으면 저장이 거부되고 이유가 보인다.
7. 탭을 옮겼다 돌아와도 방금 고친 값이 그대로다.
8. `앱` 탭에서 상한을 바꾸면 도크의 슬롯 표시기가 같은 값을 보여준다.
9. workspace를 둘 만들어 번갈아 고르면 `실행` 탭의 값이 각자의 것으로 바뀐다.
10. `정보` 탭이 MCP 포트와 DB 경로를 보여주고, 서버가 죽어 있으면 그 이유를 보여준다.
11. `e2e`가 설정 화면을 실제로 클릭해 2·5·8을 확인한다.

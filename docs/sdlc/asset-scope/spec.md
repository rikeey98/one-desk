# Spec: asset 목록 범위 확장

- 출처: `intent.md` (2026-09-09 승인)
- 작성자: 권용현
- 상태: 승인됨
- 작성일: 2026-09-09

## 요구사항

### 기능 요구사항

- **FR-1.** 스캔이 repo 루트에 더해 **글로벌 경로**를 훑는다. 기본값은 claude용
  `~/.claude/skills`·`~/.claude/agents`, opencode용 `~/.config/opencode/agent`다.
- **FR-2.** 글로벌 경로는 **설정으로 바꿀 수 있다.** claude용과 opencode용을 각각 지정한다.
- **FR-3.** 설정한 경로가 존재하지 않아도 스캔은 던지지 않고 그 경로만 건너뛴다.
- **FR-4.** 같은 파일을 두 번 훑어도 목록에 **행이 하나만** 남는다. 글로벌도 마찬가지다.
- **FR-5.** repo를 고르면 목록은 **글로벌 + 그 repo**의 asset만 보여준다. 고르지 않으면 그
  workspace에서 볼 수 있는 것을 전부 보여준다. 앱에서 작성한 것(`authored`)은 repo 선택과
  무관하게 항상 보인다.
- **FR-6.** 각 줄은 출처를 구분해 보여준다 — `글로벌` / repo 이름 / `앱에서 작성`.
- **FR-7.** 실행이 끝나면 그 workspace를 다시 훑어 목록을 갱신한다. agent가 실행 중에 만든
  skill 파일이 **새로고침 없이** 나타난다.
- **FR-8.** 설정에서 경로를 바꾸고 새로고침을 누르면 바뀐 경로의 결과가 목록에 반영된다.
- **FR-9.** 사이드바 하단에서 설정 화면을 열고 닫을 수 있다. 설정 화면은 **모달이 아니라
  본문 영역을 대신 차지하며**, 닫으면 이전 화면으로 돌아온다.

### 비기능 요구사항

- **NFR-1.** 부팅 스캔은 앱이 뜨는 것을 막지 않는다. 실패하면 목록만 낡고 앱은 정상이다.
- **NFR-2.** `core/`는 `electron`을 import하지 않는다. 홈 디렉토리는 `main`이 인자로 넘긴다
  (`CoreOptions`의 `dataDir`·`migrationsDir`·`bridgePath`와 같은 방식).
- **NFR-3.** 새 런타임 의존성을 더하지 않는다.
- **NFR-4.** 사라진 파일의 asset 행을 지우지 않는다. 과거 run의 기록이 끊기기 때문이다
  (전체 설계 §232).
- **NFR-5.** asset 이름·설명·경로는 화면에 **평문으로** 그린다. 외부에서 온 파일이라
  신뢰할 수 없는 입력이다(`2026-09-07-asset-scan-design.md` §6-3).
- **NFR-6.** 마이그레이션은 기존 데이터를 잃지 않는다.

## 범위 밖

- **플러그인이 깐 skill(이 장비 기준 63개).** 기본 경로에 넣지 않는다. 필요하면 사용자가
  설정에 경로를 더한다.
- **검색·필터·접기.** 목록이 길어지는 문제를 UI로 푸는 것은 이번이 아니다.
- **MCP 도구(`create_asset`·`list_assets`).** 조각 2로 분리했다.
- **앱에서 만든 asset을 CLI가 아는 진짜 skill로 등록하기.** 지금처럼 프롬프트에 본문으로
  실린다.
- **워크스페이스 기본값 설정(권한·모델·CLI 경로).** 전체 설계 §403이 "설정 화면"을
  전제하지만 이번에 그 화면 전체를 만들지는 않는다.

## 설계

### 개요

세 가지가 함께 움직인다.

**1) 스캔 경로를 인자로 받는다.** 지금 `scanRepo(repoPath)`는 repo 하나를 훑는다. 여기에
글로벌을 더하되 **`core/`가 홈 경로를 스스로 알지 않게** 한다(NFR-2). 스캔 서비스가
생성될 때 글로벌 루트 목록을 받고, `main`이 `app.getPath('home')`으로 채운다.

대안으로 `os.homedir()`를 `core/`에서 직접 부르는 방법이 있다. `node:os`는 electron이
아니므로 규칙 위반은 아니다. 그러나 **테스트가 실제 홈 디렉토리를 훑게 되어** 사람마다
결과가 달라진다. 인자로 받으면 임시 디렉토리로 대체할 수 있다. 인자 방식을 택한다.

**2) 동일성 키를 바꾼다.** 지금 키는 `(workspace_id, repo_id, file_path)`인데 글로벌은
`repo_id`가 NULL이고 SQLite는 유니크 인덱스에서 NULL을 서로 다른 값으로 취급한다. 그대로
두면 **스캔할 때마다 같은 글로벌 skill이 새 행으로 쌓인다.** 오류가 나지 않아 한참 모른다.

`(workspace_id, file_path)`로 바꾼다. 파일 경로 자체가 유일하므로 `repo_id`는 키에 필요
없고, 앱에서 쓴 것은 `file_path`가 NULL이라 여전히 여러 개 만들 수 있다.

**3) 출처는 기존 컬럼에서 파생한다.** 새 컬럼을 더하지 않는다.

| `source` | `repo_id` | `file_path` | 출처 |
|---|---|---|---|
| `discovered` | 있음 | 있음 | 그 repo |
| `discovered` | **NULL** | 있음 | **글로벌** |
| `authored` | NULL | NULL | 앱에서 작성 |

### 데이터 모델

**마이그레이션 `0005`.** 유니크 인덱스 `asset_discovered_idx`를 지우고
`(workspace_id, file_path)`로 다시 만든다. 컬럼 변경은 없다.

기존 행에 대한 영향: 지금 저장된 것은 전부 repo에서 발견한 것이거나 앱에서 쓴 것이라
새 키로도 충돌하지 않는다. 같은 파일이 두 repo에 동시에 등록된 경우(한 repo가 다른 repo
안에 있는 경우)에만 충돌할 수 있는데, **마이그레이션이 실패하지 않도록 인덱스를 만들기 전에
중복 행을 정리한다** — `file_path`가 같은 행 중 `created_at`이 가장 이른 것만 남긴다.

**글로벌 asset은 workspace마다 한 벌씩 저장한다.** `asset.workspace_id`가 NOT NULL이고,
이를 nullable로 바꾸면 목록·삭제·외래키가 전부 흔들린다. 글로벌 18개 × workspace 수는
무시할 만한 양이고, 조회 경로가 지금 그대로 남는다.

### 인터페이스

**설정 저장** — `app_setting`(장비 단위)에 담는다. 글로벌 skill은 workspace가 아니라 그
장비의 것이다. 기존 `run.concurrencyLimit`과 같은 방식으로, 저장소에 키별 접근자 한 쌍과
안전한 기본값을 둔다.

| 키 | 기본값 |
|---|---|
| `assets.globalRoots.claude` | `<home>/.claude/skills`, `<home>/.claude/agents` |
| `assets.globalRoots.opencode` | `<home>/.config/opencode/agent` |

값은 줄바꿈으로 구분한 경로 목록으로 저장한다. 비어 있으면 기본값을 쓴다.

**IPC** — `settings.getGlobalRoots()` / `settings.setGlobalRoots(input)` 두 채널을 더한다.
경로를 바꾸면 곧바로 다시 훑고 갱신된 목록을 돌려준다(FR-8).

**화면** — `AssetPanel`에 `repos`가 이미 내려가 있으므로 repo 필터는 `repoId`를 하나 더
받아 거른다.

경로 편집은 **사이드바 하단의 최소 설정 화면**에서 한다. 사이드바에 설정 링크를 두고,
누르면 본문 영역이 설정으로 바뀐다(인박스가 이미 쓰는 전환 방식과 같다). 모달을 쓰지
않으므로 전체 설계 §509의 근거("뒤의 목록을 계속 만질 수 있어야 한다")와 충돌하지 않는다 —
설정 화면은 목록을 만지면서 볼 화면이 아니다.

이번 설정 화면에는 **글로벌 경로 두 묶음만** 둔다. 전체 설계 §403이 전제한 workspace
기본값(권한·모델·CLI 경로)은 이 화면이 앞으로 자랄 자리이지만 이번 범위가 아니다.

### 확인되지 않은 가정

**Windows에서 `%USERPROFILE%\.claude\skills`가 실제 위치인지 확인하지 않았다.**
`os.homedir()` 기반이라 경로 자체는 맞을 것으로 보이나 실측하지 않았다. 틀리면 그 장비에서
목록이 비어 보이는데, **FR-2의 설정으로 복구되므로 차단 사항이 아니다.** Windows 장비를
쓸 기회가 생기면 확인한다.

### 예외 처리

- **경로가 없거나 읽을 수 없다** → 그 경로만 건너뛴다. 목록에 아무 표시도 하지 않는다.
  대부분의 사용자에게 opencode 전역 디렉토리는 존재하지 않는 것이 정상이다.
- **부팅 스캔 실패** → `onError`로 흘리고 앱은 정상 기동한다(NFR-1).
- **설정 저장 실패** → 화면에 오류를 띄우고 이전 값을 유지한다. 자동 저장이 아니라 사용자가
  결과를 보는 자리이므로 조용히 넘기지 않는다.
- **마이그레이션의 중복 정리** → 남기지 않은 행을 지운다. 그 행을 첨부했던 과거 run의
  `assembled_prompt`는 그대로 남는다.

## 정책 검토

| 영역 | 적용 정책 | 판단 | 근거 |
| --- | --- | --- | --- |
| 아키텍처 경계 | `core/`는 `electron`을 import하지 않는다 (CLAUDE.md) | 준수 | 홈 경로를 `CoreOptions`로 주입한다(NFR-2) |
| 아키텍처 경계 | `renderer/`는 `core/`를 import하지 않고 `window.oneDesk`는 `main.tsx`에만 (CLAUDE.md) | 준수 | 설정은 기존 IPC·preload 경로를 그대로 탄다 |
| 데이터 | 사라진 asset을 지우지 않는다 (asset 설계 §3-4) | 준수 | 스캔 규칙은 그대로다 |
| 데이터 | 시각은 epoch ms 정수, id는 `randomUUID()` (CLAUDE.md) | 준수 | 새 컬럼이 없다 |
| 의존성 | 새 런타임 의존성 금지 (asset 설계 §4) | 준수 | 경로 처리는 `node:path`·`node:fs`로 충분하다 |
| 보안 | asset 본문·이름은 신뢰할 수 없는 입력 (asset 설계 §6-3) | 준수 | 평문 렌더 유지(NFR-5). **글로벌로 범위가 넓어져 노출 면적이 커진다**는 점은 인지한다 |
| UX | 이 앱에는 모달이 없다 (전체 설계 §509, `ConfirmButton` 주석) | 준수 | 설정 화면은 모달이 아니라 본문 영역 전환이다(FR-9). 원작자 결정 |
| 설계 문서 | 설계의 결정을 임의로 바꾸지 않는다. 구멍이 보이면 지적한다 (CLAUDE.md) | 준수 | asset 설계 §3-1·§3-3을 뒤집으므로 **그 문서의 해당 절에 개정 주석을 덧붙인다**. 원작자 결정 |

## 확인 필요 항목

> 여기 남은 항목은 Claude가 임의로 결정하지 않는다.

없다. 초안에 있던 셋 중 둘은 원작자가 결정했고(설정 UI 형태 → 사이드바 하단 최소 설정
화면, 문서 처리 → 기존 문서에 개정 주석), 나머지 하나(Windows 기본 경로)는 판단이 아니라
**확인되지 않은 가정**이라 설계 절로 옮겼다. 차단 사항이 아니다.

## intent 미해결 질문에 대한 답

| 질문 | 결정 | 근거 |
| --- | --- | --- |
| 설정을 `app_setting`(장비)에 둘지 workspace에 둘지 | **`app_setting`** | 글로벌 skill은 장비의 것이다. workspace마다 다른 값을 둘 이유가 없고, 기존 `run.concurrencyLimit`과 같은 자리다 |
| 설정 화면을 어디까지 만드는가 | **사이드바 하단에 최소 설정 화면. 이번엔 글로벌 경로만 담는다** | 경로 여러 개를 인라인으로 편집하기 어렵다. 모달이 아닌 영역 전환이라 §509와 충돌하지 않고, §403이 전제한 화면이 앞으로 자랄 자리가 된다 |
| 글로벌 경로의 OS별 기본값 | `os.homedir()` 기준 `~/.claude/skills`·`~/.claude/agents`·`~/.config/opencode/agent`. **Windows 미실측** | macOS에서 앞 둘을 확인했다. Windows는 확인 필요 항목 3 |
| 글로벌 asset을 workspace마다 저장할지 한 벌만 둘지 | **workspace마다 한 벌** | `workspace_id`가 NOT NULL이고 nullable로 바꾸면 조회·삭제·외래키가 흔들린다. 18개 × workspace 수는 무시할 만하다 |
| 동일성 키를 무엇으로 바꾸는가 | **`(workspace_id, file_path)`** | 파일 경로가 유일하므로 `repo_id`가 불필요하고, `authored`는 `file_path`가 NULL이라 여러 개가 허용된다 |

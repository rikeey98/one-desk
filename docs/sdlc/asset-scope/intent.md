# Intent: asset 목록 범위 확장

- 작성자: 권용현
- 상태: 승인됨
- 작성일: 2026-09-09

## 문제

**`SKILLS / AGENTS` 패널이 비어 있어 기능을 제대로 쓰지 못했다.** 원작자의 말 그대로
"제대로 못 쓰고 있었어, 안 보이니깐."

앱은 등록된 repo의 루트 세 곳(`.claude/skills/*/SKILL.md`, `.claude/agents/*.md`,
`.opencode/agent/*.md`)만 훑는다. 그런데 실제로 쓰는 skill은 거기에 없다.

실측한 이 장비의 분포는 다음과 같다.

| 위치 | 개수 |
|---|---|
| `~/.claude/skills/` (직접 만든 것) | 18 |
| `~/.claude/plugins/` 아래 (플러그인이 깐 것) | 63 |
| 이 저장소(`one-desk`)의 `.claude/skills/` | 0 |

즉 **패널이 비어 보이는 것이 정상 동작이었다.** 사람이 손수 만든 skill 18개가 앱에서
보이지 않으니, 맥락에 담을 수도 없고 실행에 실을 수도 없었다.

부수적으로, 같은 패널이 repo 단위로 걸러지지 않는다. 이슈·메모는 repo를 고르면 그 repo
것만 보이는데 asset만 workspace 전체를 한꺼번에 보여준다.

## 원하는 결과

패널을 열면 **지금 쓸 수 있는 skill과 agent가 실제로 보인다.** 글로벌로 등록해 둔 것과
지금 보고 있는 repo의 것이 함께 보이고, 이미 있는 담기 토글로 실행에 실을 수 있다.

**repo를 골라도 놓치는 것이 없어야 한다.** 하나의 이슈가 여러 repo에 걸치는 일이 실제로
자주 있고, 어느 repo에도 묶이지 않은 "workspace 공통" 이슈·메모도 있다. repo를 고른다고
그것들이 숨으면 오히려 일을 놓친다.

목록의 최신성은 사람이 신경 쓰지 않아도 된다. agent가 실행 중에 skill 파일을 만들었다면
그 실행이 끝났을 때 목록에 나타난다.

글로벌 위치는 사람마다 다를 수 있으므로, **앱이 어디를 훑을지 사용자가 설정에서 정할 수
있다.** claude용과 opencode용을 따로 정한다.

## 영향 범위

- **사용자**: one-desk 사용자 전부. 특히 글로벌 skill을 쌓아둔 사람일수록 체감이 크다.
  배포 대상이 Windows이므로 홈 경로 기본값이 그 환경에서도 맞아야 한다.
- **시스템**:
  - `asset` 스캔(`core/assets/`) — 훑을 경로가 repo 밖으로 넓어진다
  - `asset` 저장소와 스키마 — 지금 동일성 키가 `(workspace_id, repo_id, file_path)`인데
    글로벌은 `repo_id`가 비어 이 키가 성립하지 않는다
  - 앱 설정 저장소(`app_setting`) — 글로벌 경로를 담을 자리
  - `AssetPanel` / `useAssets` — repo 필터와 실행 완료 후 갱신
  - 설정 화면 — **현재 앱에 사용자가 값을 바꿀 설정 화면이 없다.** 새로 만들어야 한다.

## 제약

- **범위 밖: 플러그인이 깐 skill 63개.** 이미 CLI가 알아서 쓰므로 맥락에 따로 담을 이유가
  적고, 한 패널에 81줄이 쌓이면 검색·접기 없이는 찾기 어렵다. 검색과 접기는 이번 범위가
  아니다. 필요하면 사용자가 설정에 경로를 직접 더한다.
- **범위 밖: agent가 MCP로 asset을 만드는 것.** 별도 과제(조각 2)로 분리했다.
- **범위 밖: 앱에서 만든 asset을 CLI가 아는 진짜 skill로 등록하는 것.** 지금처럼 프롬프트에
  본문으로 실린다.
- `core/`는 `electron`을 import하지 않는다. 홈 디렉토리 같은 경로는 인자로 받는다.
- 새 런타임 의존성을 더하지 않는다.
- 기존 데이터를 잃지 않는다. 사라진 파일의 asset 행을 지우지 않는 규칙은 그대로 지킨다.
- **repo 필터의 기존 규칙을 바꾸지 않는다.** 전체 설계 §150이 정한 대로 이슈·메모는
  workspace가 소유하고 repo 연결은 N:M 태그이며, 태그가 하나도 없으면 그것이 곧 "공통"이다.
  이번 작업이 그 규칙을 건드리면 안 된다.

## 성공 기준

1. 패널을 열면 `~/.claude/skills/`의 skill **18개가 보인다**(이 장비 기준). 지금은 0개다.
2. repo를 고르면 **글로벌 + 그 repo**의 것만 보이고, 고르지 않으면 그 workspace에서 볼 수
   있는 것이 전부 보인다.
3. 스캔을 두 번 돌려도 **같은 파일이 목록에 두 번 나타나지 않는다.**
4. 설정에서 글로벌 경로를 바꾸고 새로고침하면 그 경로의 것이 목록에 반영된다.
   claude용과 opencode용을 각각 지정할 수 있다.
5. agent가 실행 중에 repo에 skill 파일을 만들면, **그 실행이 끝난 뒤 새로고침을 누르지
   않아도** 목록에 나타난다.
6. 글로벌 경로가 존재하지 않아도 앱이 정상적으로 뜨고 목록이 비어 보일 뿐이다.

## 미해결 질문

- [ ] 설정을 어디에 두는가 — `app_setting`(장비 단위)인가 workspace 단위인가. 글로벌 skill은
      장비의 것이므로 `app_setting`이 자연스러워 보이나, 설계 단계에서 확정한다.
- [ ] 설정 화면이 없다. 이번에 어디까지 만드는가 — 이 값들만 위한 최소 화면인가, 아니면
      기존에 화면이 없던 다른 설정(동시 실행 상한 등)까지 담는 자리를 만드는가.
- [ ] 글로벌 경로의 기본값을 OS별로 어떻게 정하는가. macOS·Linux는 `~/.claude/skills`가
      확인됐고, **Windows 기본값은 실측하지 않았다.**
- [ ] 글로벌 asset을 workspace마다 한 벌씩 저장하는가, 아니면 workspace와 무관하게 한 벌만
      두는가. 지금 스키마는 `workspace_id`가 NOT NULL이다.
- [ ] 동일성 키를 무엇으로 바꾸는가. `(workspace_id, file_path)`가 후보다 — 파일 경로 자체가
      유일하므로 `repo_id`가 키에 필요 없고, 앱에서 쓴 것은 `file_path`가 비어 있어 여럿
      만들 수 있다.

# Spec: 인박스를 시간순 · workspace별 · 상태별로 본다

- 출처: 대화 (2026-10-10) — "인박스에서도 모드를 선택해서 시간순서대로 대화를 보여주는거랑(오름차순, 내림차순), workspace별로
  (repo까지) 보여주는거랑, 대화 상태 별로 보여주는거랑 추가해줘". intent는 생략했다: 보는 방식 셋과 정렬 둘을 사용자가 정했고, 화면이
  갈리는 두 가지(아래 §0)도 같은 대화에서 골랐다.
- 작성자: 권용현 (초안: Claude)
- 상태: 승인 (2026-10-10, 사용자 — "좋아 그대로 가고 plan 써줘")
- 작성일: 2026-10-10

## 0. 사용자가 정한 것 (2026-10-10)

| 질문 | 답 |
|---|---|
| 보기와 정렬을 고르는 방식 | **보기 + 정렬 따로** — 보기 세 칸(`시간순` · `workspace별` · `상태별`) 옆에 정렬 버튼(`최신 먼저` / `오래된 먼저`). 정렬은 묶음 안 순서에도 걸린다 |
| 묶음 머리 | **접을 수 있고 기억** — 도크의 repo 구획과 같다. 접어도 개수와 답변 필요는 보이고, 접은 묶음은 이 장비에 남는다 |

## 1. 범위

렌더러만 바뀐다. core·IPC·스키마·마이그레이션 없음. 인박스 목록(`runs.inbox()`)이 이미 모든 workspace의 대화마다 대표 턴 하나를
주고, 묶는 데 쓸 재료(`workspaceId`·`cwd`·`endedAt`·카테고리)가 전부 그 안에 있다. 다른 workspace의 repo 이름은 이미 있는
`repos.list(workspaceId)`를 workspace마다 부른다.

**빠지는 것**: 배지와 카테고리 규칙(`shared/inbox.ts` 그대로), 특정 workspace만 남기는 거름(묶음 접기로 대신한다), 턴 단위 보기,
도크 대화 목록의 정렬, 묶음 순서를 손으로 바꾸기.

## 2. 기능 요구사항

### (A) 보기와 정렬

- **FR-1** 인박스 목록 위에 도구 줄이 선다. 왼쪽은 보기 세 칸 `시간순` · `workspace별` · `상태별`(그룹 이름 `인박스 보기`, 칸마다
  `aria-pressed`)이다. 오른쪽은 정렬 버튼 하나로, 지금 순서를 글자(`최신 먼저` / `오래된 먼저`)와 화살표 아이콘으로 보이고 누르면
  뒤집힌다. 접근성 이름은 `정렬: 최신 먼저`처럼 지금 순서를 말한다.
- **FR-2** 시간의 기준은 그 대화 대표 턴의 **끝난 시각**(`endedAt`)이다 — 지금 항목 머리에 보이는 시각이고, 지금 목록을 정렬하는
  기준이다. `최신 먼저`는 지금 순서 그대로이고, `오래된 먼저`는 **그것을 정확히 뒤집은 순서**다(같은 시각끼리의 순서까지 뒤집힌다 —
  두 번 누르면 제자리다).
- **FR-3** 기본은 `시간순` · `최신 먼저` — 지금 화면 그대로다. 고른 보기와 정렬은 이 장비에 남는다(localStorage — 보기 취향,
  `dockSections.ts`와 같은 방식). 모르는 값이면 기본이다.
- **FR-4** 도구 줄은 항목이 하나라도 있을 때만 선다. 비면 지금처럼 `처리할 결과가 없습니다`뿐이다.

### (B) 시간순

- **FR-5** 지금처럼 한 줄 목록이다. 항목 머리의 소속이 `workspace` 하나에서 **`workspace · repo`**로 넓어진다 — repo를 모르면
  (등록하지 않은 경로, 아직 못 읽음) workspace만 쓴다.

### (C) workspace별

- **FR-6** 두 단으로 묶는다: workspace → 그 안의 repo. 항목의 repo는 대표 턴의 `cwd`와 경로가 같은 **그 workspace의** 등록
  repo다. 이어 가는 대화는 작업 디렉토리가 잠기므로(`execution.resume`이 세션 턴의 `cwd`를 쓴다) 대표 턴의 `cwd`가 곧 뿌리의
  `cwd`다. 경로 비교는 도크 구획과 **같은 함수**다(NFR-2). 맞는 repo가 없으면 그 workspace의 `기타`다.
- **FR-7** 묶음 순서는 정렬을 따른다 — **묶음의 첫 항목이 정렬에서 앞서는 순서**다. 그래서 `최신 먼저`면 가장 최근에 끝난 대화가
  있는 묶음이 위이고, `오래된 먼저`면 가장 오래 기다린 대화가 있는 묶음이 위다. `기타`는 그 workspace 안에서 늘 맨 아래다. 목록에
  없는 workspace(지워지는 중)의 묶음은 맨 아래이고 이름은 `(사라진 workspace)`다. 묶음 안은 정렬 그대로다.
- **FR-8** repo 머리는 workspace 안에 repo 묶음이 하나뿐이어도 선다 — 인박스는 workspace를 넘는 목록이라 repo가 다른 곳에 보이지
  않는다(도크 구획이 하나면 머리를 빼는 dock-repo-sections FR-5와 이유가 다르다).
- **FR-9** 묶음 안 항목의 머리에서는 workspace·repo 이름을 뺀다 — 머리가 말한다.

### (D) 상태별

- **FR-10** 인박스 카테고리(`inboxCategory`)로 묶는다. 묶음 순서는 정렬과 무관하게 **고정**이다: `답변 필요` → `실패` → `중단됨`
  → `완료 · 미확인` → `대기 중 취소됨`. 손이 필요한 것이 위다 — 배지가 세는 셋이 먼저 온다. 항목이 없는 카테고리는 묶음이 없다.
  묶음 안은 정렬 그대로다.
- **FR-11** 묶음 안 항목의 머리에서는 카테고리 칩을 뺀다(머리가 말한다). 소속(`workspace · repo`)은 남는다.

### (E) 묶음 머리

- **FR-12** 머리는 꺾쇠 · 이름 · 개수 알약이다. 누르면 접고 편다(`aria-expanded`) — 항목을 열지 않는다. 접근성 이름은
  `<이름> 묶음`이다: workspace는 `one-desk 묶음`, repo는 `one-desk · api 묶음`, 기타는 `one-desk · 기타 묶음`, 카테고리는
  `실패 묶음`이다. "접기/펼치기"를 이름에 넣지 않는다(CLAUDE.md — 턴의 `접기`와 부분 일치). workspace 머리의 개수는 그 안의 전부다.
- **FR-13** 접힌 머리는 그 안에 답변 필요가 있으면 `답변 필요` 표식을 보인다(도크 구획과 같은 규칙). 상태별의 `답변 필요` 묶음은
  이름이 곧 그것이라 표식이 없다.
- **FR-14** 접힘은 사용자가 정한다. 기본은 전부 펼침이고, 접은 묶음은 이 장비에 키로 남는다(`ws:<id>` · `repo:<id>` ·
  `other:<workspaceId>` · `status:<카테고리>` — repo id는 workspace를 넘어 유일하다). 새 항목이 와도, 보기를 바꿨다 돌아와도
  펼쳐지지 않는다. workspace를 접으면 그 안의 repo 묶음째 숨는다.
- **FR-15** 항목이 확인돼 빠지면 그 묶음의 개수가 줄고, 비면 묶음이 사라진다. 접은 기억은 남는다 — 같은 묶음에 항목이 다시 오면
  접힌 채로 온다(개수와 답변 필요가 보인다).

### (F) 다른 workspace의 repo

- **FR-16** 인박스 화면이 열려 있는 동안 workspace마다 `repos.list`로 repo를 읽는다. App이 읽어(`useInboxRepos`) 인박스에
  **필수 prop**으로 내린다 — 선택 prop이면 App의 한 줄을 지워도 조용히 컴파일되고 모든 항목이 `기타`로 간다. workspace 목록이
  바뀌면 다시 읽는다.
- **FR-17** 읽기 전에는 repo를 모르므로 항목이 `기타`(시간순·상태별에서는 workspace만)로 보이다가 읽으면 자리를 잡는다. 읽기에
  실패한 workspace는 계속 `기타`이고, 실패는 인박스의 오류 자리(`role="alert"`)에 보인다 — 조용히 삼키지 않는다.

### (G) 그대로인 것

- **FR-18** 항목 카드의 몸통(지시 첫 줄 · 오류 · 행동 버튼)과 행동(`대화 열기` · `다시 실행` · `이슈로 만들기` · `관련 이슈 닫기` ·
  `확인함` · `보관`)은 바뀌지 않는다.

## 3. 비기능

- **NFR-1** 판정(정렬 · 묶기 · 묶음 순서 · 묶음 키)은 `renderer/inboxView.ts`의 순수 함수다. 컴포넌트는 그리기만 한다. 보기·정렬·
  접힘의 기억도 같은 파일의 읽기/쓰기 함수다(저장소가 막혀도 던지지 않는다).
- **NFR-2** 경로로 repo를 찾는 것은 `renderer/conversation.ts`의 한 함수(`repoOfCwd`)다 — `repoOfConversation`이 그것을 쓰도록
  뗀다. 따로 적으면 도크 구획과 인박스 묶음이 같은 대화를 다른 repo로 부른다.
- **NFR-3** 새 이름(`인박스 보기` · `시간순` · `workspace별` · `상태별` · `정렬: …` · `<이름> 묶음`)이 기존 e2e와 부분 일치로
  부딪히지 않는지 전체 e2e로 본다. 기본 보기가 지금 화면이라 기존 인박스 e2e의 셀렉터(`.inbox-list > li` · `.inbox-item`)는
  시간순에서 그대로 맞는다.
- **NFR-4** 색은 토큰만, 글꼴은 rem, 아이콘은 `icons.tsx`(`IconChevronRight` · `IconArrowDown`)다. 보기 세 칸은 상세 본문의
  `보기 방식` 토글과 같은 모양이고, 묶음 머리는 도크 구획 머리와 같은 무게다 — 이름을 대문자로 바꾸지 않는다.

## 4. 우려

1. 항목을 처리할 때마다 workspace별 묶음이 자리를 바꿀 수 있다(FR-7 — 묶음 순서가 첫 항목을 따른다). 도크 구획이 최근 활동순인
   것과 맞췄다. 자리가 고정돼야 한다면 사이드바 순서(이름순)로 바꾸는 것이 대안이다.
2. repo 경로를 설정에서 바꾸면 옛 대화의 `cwd`는 옛 경로라 `기타`로 간다 — 도크 구획(dock-repo-sections §4의 1)과 같다. 받아들인다.
3. 인박스를 열 때마다 workspace 수만큼 `repos.list`가 돈다. 행이 작고 로컬 SQLite라 받아들인다.

## 5. 검증

- 단위(`inboxView.test`): 최신/오래된 먼저가 정확한 역순, workspace → repo 묶기(경로 끝 구분자 · Windows 대소문자 · 다른 workspace의
  같은 경로 repo는 잡지 않음 · 없으면 기타), 묶음 순서가 정렬을 따름, 기타와 사라진 workspace가 맨 아래, 상태 묶음의 고정 순서와 빈
  카테고리 생략, 기억(모르는 값 → 기본, 막힌 저장소).
- 컴포넌트(`InboxPanel.test`): 보기 전환, 정렬 뒤집기, 머리 접기와 기억, 접힌 머리의 답변 필요, 보기마다 항목 머리에서 빠지는 것,
  다시 마운트해도 보기·정렬이 남음, 카테고리별 행동 집합 표(기존)가 그대로.
- 배선(`App.test`): 인박스 항목에 다른 workspace의 repo 이름이 보인다 — App이 repo를 내리지 않으면 빨개진다.
- e2e: repo가 있는 workspace에서 대화를 돌린 뒤 인박스에서 `workspace별` → `<ws> · <repo> 묶음`, `상태별` → `완료 · 미확인 묶음`,
  정렬 뒤집기.
- 실제 앱 캡처(라이트·다크).

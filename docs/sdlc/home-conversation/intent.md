# Intent: workspace를 넘어 "내가 뭘 하고 있었나"를 agent에게 묻기

- 출처: 대화 (2026-10-26) — "one-desk에 현재 열려있는 대화를 쭉 분석해서 … 내가 뭐하고 있었는지 뭐해야하는지 에이전트로
  분석하고 싶어서" → "워크스페이스 위에 상위 개념을 두고 모든 워크스페이스의 대화를 가져와서 보고싶은데" → 안 A·B 중
  "A 홈 대화로 만들어보고 싶어"
- 작성자: 권용현 (초안: Claude)
- 상태: 승인 (2026-10-26, 사용자 "spec으로 넘어가자") — spec은 같은 폴더

## 정해진 것 (2026-10-26, 사용자)

- **새 엔티티(그룹)를 만들지 않는다.** 홈이 이미 workspace 위의 층이므로 그 자리를 쓴다(안 A). 그룹(안 B — `workspace.group_id`)은
  섞이면 안 되는 묶음이 실제로 생기면 그때 본다.
- **전체 설계 §8의 "agent는 토큰의 workspace만 본다"를 이 대화 하나에 한해 사용자가 명시적으로 뒤집는다.** MCP 상시 기동이
  §14를 뒤집은 것과 같은 방식으로, 근거를 spec에 남긴다.

## 문제

열려 있는 대화가 여러 workspace에 흩어져 있다. "어제 무엇을 하다 말았고 오늘 무엇부터 해야 하나"를 알려면 workspace를 하나씩
골라 도크의 대화를 열어 봐야 한다. 홈은 할 일을 **줄**로 모아 주지만(답변 필요·실패·훑기·방치), 대화가 **무엇에 관한 것이었고
어디까지 갔는지**는 말하지 않는다. 그것은 읽고 요약하는 일이라 agent가 잘한다.

그런데 agent에게 시킬 수가 없다. MCP의 `list_conversations`·`get_conversation`은 이미 대화를 읽지만 토큰의 workspace 하나에
묶여 있어, workspace마다 대화를 하나씩 열고 같은 지시를 보내 결과를 손으로 합쳐야 한다. 리포트의 `agent에게 다듬기`는
workspace를 넘지만 대화를 제목 한 줄로만 싣고, 사람이 기간·workspace를 골라 메모를 만든 뒤에야 agent에게 간다.

## 원하는 결과

홈에서 **"홈 대화"** 를 열어 "열려 있는 대화 전부 보고, 내가 뭐 하고 있었는지랑 다음에 할 일 정리해줘"라고 보내면, agent가
**모든 workspace의** 대화·이슈·메모를 읽고 workspace를 가로질러 한 번에 답한다. 이어 물을 수 있다("회사 쪽만 다시", "api
repo에서 멈춘 대화 자세히").

이 대화는 **읽기 전용**이다 — 다른 workspace의 데이터는 읽기만 하고, 파일도 고치지 않는다. 결과를 남기고 싶으면 사람이 답을
복사하거나 메모로 저장한다(아래 미해결).

## 영향받는 것

- 사람: 여러 workspace를 오가는 사용자(회사 일·개인 프로젝트).
- 코드:
  - MCP 토큰의 범위 — 지금 `RunContext`는 `workspaceId` 하나다(`core/mcp/host.ts`). 범위가 "모든 workspace"인 토큰이 생긴다.
  - MCP 도구 — `list_workspaces`가 새로 필요하고, `list_conversations`·`get_conversation`·`list_issues`·`get_issue`·`list_memos`·
    `get_memo`가 workspace를 넘어 읽어야 한다. 소속 검사(`loadIssue`·`loadMemo`)가 지금은 "토큰의 workspace"다.
  - `core/index.test`의 "홈은 MCP deps에 없다"·"reports는 MCP deps에 없다" — 이 규칙이 무엇을 지키는지 다시 정해야 한다.
  - 홈 화면(`HomePanel`) — 대화를 여는 자리, 그리고 대화가 이어지는 자리.
- 데이터: run은 지금 workspace 하나에 속하고 `cwd`가 그 workspace의 repo다. 홈 대화를 **어디에 저장하고 어디서 띄우나**가 이
  일의 핵심 질문이다(아래 미해결).

## 제약

- **넓어진 범위는 읽기 전용에만 준다.** workspace를 넘어 **쓰는** 길은 만들지 않는다 — 회사 workspace의 이슈를 개인 쪽 대화가
  바꾸면 감사 기록(§8 "감사 기록")이 그 경계를 설명하지 못한다.
- **범위는 렌더러가 정하지 못한다.** 일반 run이 렌더러의 요청으로 넓은 토큰을 얻는 길이 없어야 한다 — 홈 대화라는 사실을 core가
  판정한다(`core.panelScope`가 창의 범위를 검증하는 것과 같은 결).
- **workspace 하나에 묶인 일반 대화의 MCP는 그대로다.** 지금 도는 모든 run의 도구 목록과 응답 모양이 바뀌지 않는다.
- 세 경계(`core/`는 electron 없음 · renderer는 core 없음 · IPC는 얇다), App이 내리는 prop은 필수, 짧은 새 이름은 e2e 부분 일치를 본다.
- 대화를 읽는 도구가 주는 글은 지금처럼 잘린 앞부분이다(턴마다 지시 500자·답 1000자). 늘리면 workspace가 많을 때 한 번의
  호출이 커진다 — 늘릴지는 spec에서 잰다.

## 범위 밖

- 홈 대화가 **다른 대화를 조종**하는 것(이어 보내기·끝내기·멈추기·이름 바꾸기). 읽고 정리만 한다. 조종은 `issue-flow`의 "agent가
  정리를 제안한다"와 함께 따로 본다.
- workspace 그룹(안 B).
- 정해진 시각에 저절로 도는 요약(아침 브리프). 사람이 보낼 때만 돈다.

## 미해결 질문

- **홈 대화는 어디에 저장하나.** run은 `workspace_id`가 필요하다. (가정: **workspace에 속하지 않는 run** — 대신 새 컬럼이나 특별한
  값을 두는 것은 마이그레이션이다. 대안: 홈 대화용으로 숨긴 workspace 하나를 만든다 — 스키마는 그대로지만 사이드바·리포트·인박스가
  그것을 걸러야 한다. 대안 2: 사용자가 고른 workspace에 저장하되 토큰만 넓힌다 — 가장 싸지만 "그 workspace의 대화"로 보여 인박스·
  도크에 섞인다.) spec에서 셋을 비교해 고른다.
- **어디서 띄우나(cwd).** 읽기 전용이고 파일을 볼 일이 없다. (가정: 앱 데이터 폴더 아래 빈 폴더 — repo의 `CLAUDE.md`·skill이 끼어들지
  않는다. WSL repo는 상관없다 — 홈 대화는 늘 Windows 쪽 claude.)
- **대화록은 어디에 그리나.** (가정: 홈 화면 안에 도크와 같은 `ConversationPanel`을 그린다. 대안: 지금 홈의 새 대화 카드처럼 보내면
  다른 화면으로 옮겨 가기 — 그러면 갈 화면이 없다.)
- **홈 대화는 여러 개인가.** (가정: 여럿이고 도크처럼 목록이 있다 — 하루에 하나씩 쌓인다. 대안: 늘 하나를 이어 간다 — 맥락 창이 차면
  끝이다.)
- **인박스·홈 배지·리포트에 나오나.** (가정: 인박스와 홈 배지에는 나온다 — 답변 필요·실패면 사람이 알아야 한다. 리포트의 workspace별
  집계에는 넣지 않는다.)
- **결과를 메모로 남기는 길.** 홈 대화는 쓰기가 없으니 `create_memo`를 못 쓴다. (가정: 답 칸의 `응답 복사`로 충분하다. 대안: 홈
  대화에만 "고른 workspace 하나에 메모 저장" 버튼 — 리포트의 `<workspace>에 메모로 저장`과 같은 사람의 버튼.)
- **어느 workspace까지 읽나.** (가정: **전부**. 대안: 리포트처럼 체크 — 빼고 싶은 workspace가 있으면.)
- **agent 종류.** (가정: claude만 — 홈의 새 대화 카드와 같은 기본값 유도. OpenCode도 MCP를 쓰니 막을 이유는 없지만 spec에서 확인.)

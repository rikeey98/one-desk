# Spec: agent 준비 상태와 실행 조건(모델·effort)

- 출처: `intent.md` (2026-09-22 승인)
- 작성자: 권용현
- 상태: 승인됨 (2026-09-22)
- 작성일: 2026-09-22

## 요구사항

### 기능 요구사항 — 준비 상태

- **FR-1.** agent의 준비 상태를 **세 칸이 쌓여** 만든다. 각 칸은 앞 칸이 통과해야 돈다.
  1. **실행 파일** — 지금의 `preflight`(경로 탐색 + 접근 검사 + `.cmd` 거부). 값싸다.
  2. **인증** — `claude auth status --json` / `opencode auth list`.
  3. **모델** — claude만. `system/init`의 `model`.
- **FR-2.** **인증이 확인되지 않으면 모델 칸을 돌리지 않는다.** init은 인증을 보지 않으므로
  (intent 실측: 토큰 없이도 `claude-opus-5[1m]`가 온다) 인증 없이 얻은 모델 이름을 화면에
  올리면 못 돌리는 사람에게 초록을 보여주게 된다. 건너뛴 칸은 **"확인하지 않음"으로 보인다.**
- **FR-3.** 세 상태를 **서로 다른 말로** 구분해 보여준다 — `됨` · `안 됨(이유)` ·
  **`확인할 수 없음(이유)`**. 조회가 실패한 것을 "안 됨"으로 적지 않는다. 특히
  **자격 증명 조회에 실패한 것과 자격 증명이 0개인 것은 다른 말이다.**
- **FR-4.** 준비 상태 조회는 **요금을 만들지 않는다.** `init`을 받는 즉시 `SIGKILL`한다
  (슬래시 커맨드 `FR-10`과 같은 규칙). 인증 조회와 모델 목록 조회는 모델을 부르지 않는다.
- **FR-5.** 준비 상태 조회는 **`RunManager`를 타지 않는다.** 실행 슬롯·큐·`run` 테이블·
  `onRunUpdate` 어디에도 흔적이 남지 않는다(슬래시 커맨드 `FR-11`과 같은 규칙).
- **FR-6.** 준비 상태 조회가 실패하거나 느려도 **실행은 지금과 똑같이 된다.** 실행 버튼을
  이 결과로 막지 않는다.
- **FR-7.** 설정 화면의 `실행` 탭이 두 agent의 준비 상태를 보여주고 **`다시 확인` 버튼**으로
  다시 조회한다. 실행 파일 칸은 **지금처럼 즉시** 그려지고, 느린 두 칸은 뒤따라 채워진다.

### 기능 요구사항 — 모델

- **FR-8.** 모델 칸은 **자유 입력을 유지한다.** 제안에 없는 이름도 그대로 저장되고 실행에
  쓰인다. 빈 칸은 지금처럼 "CLI 자신의 기본값"이다.
- **FR-9.** 모델 칸에 **제안 목록**이 붙는다. agent에 따라 출처가 다르다.
  - **OpenCode** — `opencode models`가 준 목록(실측 382개). **인증과 무관하게** 조회된다.
  - **Claude Code** — 조회 수단이 없으므로 **앱이 가진 별칭 표**(`renderer/permission.ts`와
    같은 성격의 표시용 표).
- **FR-10.** claude의 모델 칸 아래에 **probe가 해석한 이름**을 보여준다(`sonnet` →
  `claude-sonnet-5`). 이것은 **"이 이름으로 넘어간다"이지 "이 모델로 돈다"가 아니다** —
  init은 모델을 검증하지 않는다(intent 실측: `gpt-9`가 그대로 통과). 문구가 이 선을 넘지
  않는다.
- **FR-11.** 같은 제안·해석이 **설정 화면과 실행 패널 양쪽**에 있다. 두 화면이 같은 값을
  다른 말로 부르면 안 된다.

### 기능 요구사항 — effort

- **FR-12.** Claude Code에 **effort 드롭다운**이 붙는다 — `low` · `medium` · `high` ·
  `xhigh` · `max`, 그리고 **`기본값`(빈 값)**. 빈 값이면 `--effort`를 붙이지 않는다.
  모델 칸의 "비우면 CLI 기본값" 규칙과 같다.
- **FR-13.** OpenCode는 **`variant` 자유 입력 칸**이다. provider마다 값이 달라 다섯 단계
  표로 묶으면 그 표가 거짓말이 된다(전체 설계 §199가 모델을 가른 것과 같은 이유).
- **FR-14.** 둘 다 **workspace 기본값으로 저장되고** 실행 패널에서 그 run에만 덮어쓸 수
  있다. agent·모델·권한과 같은 규칙이다.
- **FR-15.** 실행에 쓰인 effort/variant가 **`run` 행에 남는다.** 어느 CLI도 되돌려 주지
  않으므로(`run-info` 실측) **앱이 보낸 값이 유일한 기록**이다.

### 비기능 요구사항

- **NFR-1.** **마이그레이션 `0007`이 필요하다 — 컬럼 추가만.** `run` 테이블을 다시 만들면
  `DROP TABLE`이 `run_context_item`의 cascade를 태워 맥락 기록이 전부 지워진다(CLAUDE.md).
- **NFR-2.** 경계 셋을 지킨다. `core/`는 `electron`을 import하지 않고, `renderer/`는
  `core/`를 import하지 않으며, IPC 핸들러는 얇다.
- **NFR-3.** **CLI를 띄우는 방식이 두 벌이 되지 않는다.** 모델 probe는 슬래시 커맨드
  probe와 같은 함수·같은 인자·같은 캐시를 쓴다. 실행 파일 해석은 `resolveAgentPath` →
  어댑터 `preflight`를 그대로 탄다.
- **NFR-4.** **`checkAgents`의 기존 계약이 바뀌지 않는다.** 실행을 막는 것과 같은 판정이
  같은 자리에 남고, 느린 칸은 **별도 메서드**로 붙는다(설계 참고). 갈라지면 설정 화면과
  실행 버튼이 다른 말을 한다.
- **NFR-5.** **자격 증명을 읽지 않는다.** `auth.json` 같은 자격 증명 파일을 열지 않고,
  CLI가 공개한 명령의 출력만 읽는다. 계정 식별 정보(`email`·`orgId`·`orgName`)는
  **DB·로그·화면 어디에도 넣지 않는다**(아래 확인 필요 항목).
- **NFR-6.** 새 런타임 의존성을 더하지 않는다. ANSI 제거는 정규식 하나로 한다.
- **NFR-7.** CLI 출력·모델 이름은 화면에 **평문으로** 그린다. 외부에서 온 문자열이지
  신뢰된 마크업이 아니다.
- **NFR-8.** **조회가 실행을 느리게 하지 않는다.** 준비 상태 조회는 실행 경로 밖에 있고,
  `buildCommand`에 더해지는 것은 인자 한 쌍뿐이다.
- **NFR-9.** 색은 `:root` 토큰에서만 온다. 상태의 좋고 나쁨을 **색으로만** 구분하지 않는다
  (`DESIGN.md`).

## 범위 밖

- **실제로 한 마디를 호출해 검증하기.** 요금이 들고 느리다(intent 결정). 그래서 **없는
  모델 이름**과 **만료된 토큰**은 이 화면이 못 잡는다.
- **OpenCode의 실제 모델 관측.** 스트림이 모델을 주지 않는다(`run-info` 실측). opencode는
  "무엇을 넘겼나"까지만 안다.
- **effort를 대화록에 표시하기.** 이 작업은 **고르고 넘기고 남기는 것**까지다. `run-info`가
  만든 턴 머리 줄에 얹는 것은 그다음이다.
- **요금제 소진율**(`rate_limit_info`), 사용량·비용 — `run-info`가 다룬다.
- **인증을 앱에서 수행하기.** `claude auth login`은 대화형이라 헤드리스에서 돌 수 없다.
  화면은 **무엇을 쳐야 하는지 알려주기만** 한다.
- **`--agent` 플래그**(두 CLI 모두 있다). 이번에 다루지 않는다.

## 설계

### 개요

넷이 함께 움직인다.

**1) 준비 상태는 빠른 칸과 느린 칸으로 갈린다.** 지금 `checkAgents`는 파일 검사뿐이라
workspace를 고를 때마다 불러도 즉시 그려진다. 여기에 1~1.6초짜리 조회를 합치면 **그 즉시성이
사라진다.** 그래서 `checkAgents`는 그대로 두고 **`probeAgents`를 새로 둔다.** 화면은 둘을
같이 부르고, 빠른 결과로 먼저 그린 뒤 느린 결과가 오면 채운다.

**2) 모델 probe는 슬래시 커맨드 probe와 같은 호출이다.** `probeCommands`는 이미
`system/init`을 파싱해 슬래시 커맨드만 꺼내고 **`model`·`claude_code_version`을 버린다.**
`ProbeResult`를 넓혀 그것들을 함께 싣고, `createCommandService`의 cwd별 캐시를 그대로 쓴다.
**CLI를 한 번 더 띄우지 않는다**(NFR-3) — 실행 패널이 슬래시 커맨드 때문에 이미 돌린
probe의 결과를 설정 화면이 나눠 쓴다.

**3) 인증 조회는 probe와 별개다.** 수단도 비용도 다르다(0.24초 vs 0.9초). 그리고
**인증이 먼저 판정돼야 모델 probe를 돌릴지 정할 수 있다**(FR-2).

**4) effort는 모델과 같은 자리를 그대로 따라간다.** 컬럼도 UI도 저장도 모델이 이미 만든
모양(agent별로 갈린 workspace 기본값 + run 단위 덮어쓰기)을 복제한다. 새 개념이 아니다.

### 데이터 모델

**마이그레이션 `0007` — 컬럼 추가만.**

| 컬럼 | 테이블 | 뜻 | NULL |
|---|---|---|---|
| `default_effort_claude` | `workspace` | claude의 `--effort` 기본값 | CLI 기본값에 맡긴다 |
| `default_variant_opencode` | `workspace` | opencode의 `--variant` 기본값 | 〃 |
| `effort` | `run` | 이 run에 실제로 넘긴 값 | 넘기지 않았다 |

**두 컬럼으로 가른 이유는 모델과 같다**(전체 설계 §199). 하나로 합치면 agent를 바꾼 순간
claude의 `high`가 opencode의 `--variant`로 넘어가는데, 두 값의 의미가 다르다.

**`run`은 컬럼 하나다.** 그 행은 `agent_kind`를 이미 알고 있어 해석이 갈리지 않는다 —
`run.model`이 지금 그렇게 동작한다.

**관측본 컬럼은 만들지 않는다.** `actual_model`이 있는 이유는 CLI가 모델을 되돌려 주기
때문이고, effort는 되돌려 주지 않는다(intent 실측). `effort`에 들어 있는 값은 **요청이자
기록의 전부**다.

**준비 상태는 저장하지 않는다.** 발견된 사실이지 기록할 데이터가 아니다(슬래시 커맨드가
캐시를 프로세스 수명에만 두는 것과 같은 판단). 앱을 껐다 켜면 다시 조회한다.

### 인터페이스

**core — 준비 상태**

```
workspaces.checkAgents(workspaceId)   // 기존 그대로. preflight만. 값싸다
workspaces.probeAgents(workspaceId)   // 새로. 인증 + 모델. 느리다
```

`probeAgents`가 돌려주는 모양(`shared/models.ts`):

```ts
export type AgentAuth =
  | { state: 'ok'; method: string | null; plan: string | null }
  | { state: 'none'; hint: string }       // 로그인이 안 돼 있다
  | { state: 'unknown'; reason: string }  // 조회를 못 했다 — 'none'이 아니다

export type AgentModel =
  | { state: 'resolved'; model: string }  // init이 해석해 준 이름
  | { state: 'skipped'; reason: string }  // 인증 없음 / cwd 없음 / opencode
  | { state: 'unknown'; reason: string }  // 조회 실패

export interface AgentProbe {
  auth: AgentAuth
  model: AgentModel
  version: string | null
  /** 모델 칸의 제안 목록. opencode는 조회값, claude는 빈 배열(화면의 표를 쓴다) */
  models: string[]
}
export type AgentProbes = Record<AgentKind, AgentProbe>
```

**세 상태를 타입으로 가른 것이 FR-3이다.** `ok: boolean`에 `reason`을 붙이는 지금 모양으로는
"안 됨"과 "확인할 수 없음"이 같은 칸에 들어간다.

**core — 인증 조회**

- **claude**: `auth status --json`(JSON이 기본 출력, 0.24초). `loggedIn`이 참이면 `ok`,
  거짓이면 `none`. **서브커맨드가 없거나 실패하면 `unknown`** — 옛 버전을 "로그인 안 됨"으로
  단정하지 않는다.
- **opencode**: `auth list`. **ANSI 이스케이프를 제거한 뒤** `N credentials`를 읽는다.
  `0`이면 `none`, 1 이상이면 `ok`, **읽어내지 못하면 `unknown`**(FR-3).
  `auth.json`은 열지 않는다(NFR-5).

**core — 모델 probe**

`core/commands/probe.ts`의 `ProbeResult`에 `model`·`version`을 더한다. 파서는 이미 그 줄을
손에 들고 있다. `createCommandService`의 캐시가 그대로 둘을 나른다.

- **cwd** — 실행 패널이 쓰는 것과 같아야 한다. 설정 화면에는 "그 repo"가 없으므로
  **workspace의 첫 repo**를 쓴다. repo가 없으면 `skipped`("repo를 등록하면 확인합니다").
  repo의 `.claude/settings.json`이 모델을 정할 수 있어 cwd가 결과를 바꾼다 — **아무 데서나
  돌리면 실행과 다른 답이 나온다.**
- **opencode** — `system/init`에 해당하는 것이 없으므로 항상 `skipped`. 대신 `models`를
  채운다.

**core — 모델 목록**

`opencode models`를 **실행 파일마다 한 번** 조회해 캐시한다(cwd와 무관하다). 슬래시 커맨드
캐시와 같은 수명이다.

**어댑터**

```
claudeCode.buildCommand:  if (spec.effort) args.push('--effort', spec.effort)
opencode.buildCommand:    if (spec.effort) args.push('--variant', spec.effort)
```

`ResolvedRunSpec`에 `effort: string | null`이 더해진다. **`--effort`는 `--model` 바로
옆자리다** — 둘 다 "무엇으로 돌릴지"다.

**화면**

- `SettingsPanel` `실행` 탭 — 상태 줄이 세 칸을 보여주고 `다시 확인` 버튼이 붙는다.
  effort/variant 칸이 모델 칸 옆에 선다.
- `RunPanel` — effort/variant 칸, 모델 칸의 제안과 해석 결과 줄.
- **제안 표와 effort 표는 `renderer/`의 표 하나씩이다.** `renderer/permission.ts`가
  권한 세 단계의 화면 이름을 한 곳에 둔 것과 같다 — 두 화면이 같은 값을 다른 말로 부르지
  않게 한다(FR-11). 이것은 "의도된 중복" 규칙의 예외가 아니라 그 규칙이 이미 밝혀 둔
  **"갈라질 일이 없는 표시 문자열"** 쪽이다.

### 예외 처리

- **인증 조회가 실패하면** `unknown`이고 모델 probe는 **돌린다.** 인증을 모르는 것과 없는
  것은 다르다 — 모른다는 이유로 정보를 감추면 조회 수단이 없는 옛 CLI에서 화면이 빈다.
  화면은 "인증 확인 불가"와 모델 이름을 함께 보여주고, 모델 이름에 단정을 붙이지 않는다.
- **인증이 `none`이면** 모델 probe를 건너뛴다(FR-2). 0.9초와 훅 한 번을 아낀다.
- **probe가 타임아웃되면** `unknown`. 기존 10초 제한을 그대로 쓴다.
- **실행 파일이 없으면**(`preflight` 실패) 뒤의 두 칸을 아예 돌리지 않는다.
- **`opencode models`가 실패하면** 제안 목록이 빈다. **칸은 그대로 쓸 수 있다**(FR-8).
- **effort에 표에 없는 값이 들어오면**(DB를 손으로 고친 경우) 드롭다운이 그 값을 잃지
  않는다 — 실행 패널의 `작업 디렉토리`가 없는 경로를 `(없는 경로)`로 보여주는 것과 같은
  규칙이다. `select`에 없는 값을 주면 브라우저가 `''`로 정규화해 문제가 화면에서 사라진다.
  **CLI는 이 값을 검증하지 않는다** — `--effort bogus`도 오류 없이 통과한다(2026-09-22
  실측, init 954ms 정상 도착). 즉 **드롭다운이 유일한 가드다.**
- **조회가 늦게 도착하면** 마지막으로 보낸 것만 반영한다. `SettingsPanel`의 `checkSeq`가
  이미 그 가드를 쓰고 있다 — `probeAgents`에도 같은 것이 필요하다.

## 정책 검토

- **CLAUDE.md 경계 셋** — 준수한다(NFR-2). CLI를 띄우는 것은 전부 `core/`다.
- **전체 설계 §199** — 모델을 agent별로 가른 근거가 effort/variant에 그대로 적용된다.
- **전체 설계 §403** — workspace 기본값은 설정 화면에서 바꾼다. effort가 그 목록에 더해진다.
  **별도 확인 절차는 권한에만 걸린다** — effort는 위험한 값이 아니다.
- **전체 설계 §595** — "실행이 막힘 → 설정에서 경로 지정" 고리를 이 작업이 한 칸 넓힌다
  ("실행이 실패함 → 설정에서 로그인 상태 확인").
- **슬래시 커맨드 FR-10·FR-11** — probe가 요금을 만들지 않고 run 기록을 남기지 않는다는
  규칙을 그대로 물려받는다(FR-4·FR-5).
- **의도된 중복 규칙** — 이슈·메모 대칭을 건드리지 않는다. claude/opencode 쌍은 **갈라져야
  하는 쪽**이고(§199), 표시 문자열 표는 **공유하는 쪽**이다.
- **헤드리스 권한 규칙** — 해당 없음. `ask`를 만들 자리가 없다.
- **데이터 규칙** — 시각은 epoch ms 정수, 쓰기는 트랜잭션. `updateDefaults`는 **부분 갱신을
  받지 않는다**는 기존 규칙이 새 두 값에도 걸린다(전부 받는다).
- **`DESIGN.md`** — 색 토큰만, 안내문은 `--text-muted`, 상태를 색으로만 구분하지 않는다.

## 확인 필요 항목

- **계정 정보를 화면에 올릴지.** `auth status`는 `email`·`orgId`·`orgName`을 돌려준다.
  지금 spec은 **보여주지 않는 쪽**으로 정했다(NFR-5) — 계정이 하나뿐인 장비에서 새 정보가
  없고, e2e 스크린샷과 캡처에 섞인다. 계정을 여럿 오가는 상황이 생기면 뒤집을 값어치가
  있다. → 사용자 판단.
- **모델 probe를 자동으로 돌릴지.** 지금 spec은 **슬래시 커맨드 probe에 얹는다**고 정했다
  (NFR-3). 그 probe는 이미 실행 패널이 cwd마다 자동으로 돌리므로 **새로 도는 CLI가 없다.**
  다만 설정 화면을 열기만 해도 그 cwd의 probe가 처음 돈다면 **사용자의 `SessionStart` 훅이
  그 시점에 돈다.** 실행 패널에서 이미 일어나는 일이지만 자리가 하나 늘어난다.
  → 자동으로 두되, 훅이 무거운 환경에서 불평이 나오면 `다시 확인` 버튼 전용으로 좁힌다.
- **claude 별칭 표가 낡는 속도.** 하드코딩이라 새 모델이 나오면 제안에서 빠진다. 자유
  입력이 남으므로 **막히지는 않는다**(FR-8)는 것이 이 결정의 전제다. 표를 갱신하는 책임이
  누구에게도 없다는 점은 남는 부채다.
- **`opencode auth list` 출력 파싱의 안정성.** ANSI 박스 그림이고 기계용 형식이 없다
  (intent 실측). 버전이 올라가면 깨질 수 있다 — 깨지면 `unknown`으로 떨어져 **거짓을 말하지
  않는 것**까지가 이 spec의 보장이다.
- **`--effort`가 헤드리스에서 받아들여지는 것은 확인했다**(2026-09-22, `-p
  --output-format stream-json`과 함께 `high`·`max` 모두 init 정상 도착). 다만 **값에 따라
  결과가 달라지는지는 재보지 않았고, 앱이 검증할 방법도 없다** — 스트림이 되돌려 주지
  않는다. 그리고 **CLI가 값을 검증하지 않는다**(`--effort bogus`도 통과). 그래서 이 기능이
  주는 보장은 "**고른 값이 인자로 나간다**"까지다. 수용 기준 6이 그 선에 맞춰져 있다.
- **opencode를 이 장비에서 끝까지 검증할 수 없다.** 자격 증명이 0개다. `models`·`auth list`
  경로는 확인되지만 **`--variant`를 실은 실행**은 로그인 없이 못 돌린다. → 가짜 CLI로
  인자 조립까지만 고정한다(`*.command.test.ts`).

## intent 미해결 질문에 대한 답

- **opencode 준비 상태를 무엇으로 판정할지** → **`auth list` 출력을 ANSI 제거 후 파싱한다.**
  `auth.json`은 열지 않는다 — 자격 증명 파일이고 형식이 문서화돼 있지 않다. 읽어내지 못하면
  `unknown`이지 `0개`가 아니다(FR-3).
- **상태 조회를 언제 도는지** → **칸마다 다르다.** 실행 파일은 지금처럼 workspace를 고를
  때마다(값싸다), 인증은 함께 자동으로(0.24초, 훅 없음), 모델은 슬래시 커맨드 probe의
  캐시에 얹혀서. `다시 확인` 버튼이 전부를 다시 돌린다.
- **probe에 어느 cwd를 쓸지** → **workspace의 첫 repo.** repo의 설정이 모델을 바꿀 수 있어
  아무 데서나 돌리면 실행과 다른 답이 나온다. repo가 없으면 `skipped`.
- **claude 별칭 표를 어디에 둘지** → **`renderer/`의 표시용 표 하나.**
  `renderer/permission.ts`와 같은 자리다. `--help` 파싱은 산문이라 안 한다.
- **effort 기본값을 무엇으로 할지** → **빈 값(= CLI 기본값).** 모델 칸과 같은 규칙이고,
  드롭다운에 `기본값` 항목이 하나 더 붙는다(FR-12).
- **opencode `--variant`를 이번에 넘길지** → **넘긴다. 컬럼은 따로 둔다**(FR-13).
  claude의 `high`와 opencode의 `high`는 다른 것을 가리킨다.
- **실행 패널에도 상태를 보여줄지** → **모델 해석 결과만.** 준비 상태 전체 블록은 설정
  화면의 몫이다(FR-10·FR-11). 실행 직전에 필요한 것은 "지금 무엇으로 돈다"이지 진단이 아니다.
- **만료된 토큰** → **범위 밖.** `loggedIn: true`인데 만료된 경우는 실제 호출 전까지
  드러나지 않는다. 화면 문구가 그것까지 약속하지 않는 것으로 갈음한다.

## 수용 기준

1. 자격 증명이 0개인 OpenCode가 설정 화면에서 **초록이 아니고**, 무엇을 쳐야 하는지가
   그 자리에 적혀 있다.
2. **로그인하지 않은 Claude Code도 초록이 아니다** — init이 모델 이름을 되돌려 주더라도
   화면은 "로그인 필요"를 먼저 말하고 모델 칸은 "확인하지 않음"이다.
3. 인증 조회 **실패**는 "로그인 안 됨"과 **다른 문구**로 보인다.
4. 모델 칸을 **비운 채로** 설정 화면을 열면 claude가 실제로 쓸 이름
   (예: `claude-opus-5[1m]`)이 보인다.
5. 모델 칸에 몇 글자를 치면 후보가 보이고, **후보에 없는 이름도 그대로 저장돼 실행에
   쓰인다.**
6. effort를 `high`로 고르고 돌리면 `--effort high`가 인자에 실리고, 비우면 그 인자가
   **아예 없다.**
7. OpenCode로 바꾸면 effort 드롭다운이 사라지고 variant 칸이 나오며, claude에 넣어 둔
   값이 그 칸으로 **새지 않는다.**
8. 앱을 껐다 켜도 지난 대화가 무슨 effort로 돌았는지 `run` 행에 남아 있다.
9. 준비 상태 조회가 실패하거나 느려도 **실행은 정상으로 된다.**
10. 준비 상태 조회로 `run` 행이 생기지 않고 실행 슬롯이 점유되지 않는다.
11. 모델 probe 때문에 CLI가 **새로 뜨지 않는다** — 슬래시 커맨드 probe가 이미 돈 cwd에서는
    캐시를 쓴다.
12. 인증이 `none`이면 모델 probe가 **돌지 않는다.**
13. `e2e`가 설정 화면을 실제로 클릭해 1·5·6을 확인한다.
14. 기존 단위 테스트와 e2e가 전부 통과한다.

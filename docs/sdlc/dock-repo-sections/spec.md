# Spec: 도크 대화 목록을 repo로 나눈다

- 출처: 대화 (2026-10-07) — "대화 목록창에 repo 별로 대화를 정리해서 보고 싶어". intent는 생략했다: 문제(대화가 어느 repo의
  것인지 한 목록에 섞여 있다)와 방향을 같은 대화에서 사용자가 골랐다.
- 작성자: 권용현 (초안: Claude)
- 상태: 승인 (2026-10-07, 사용자 — "릴리스까지 진행해줘")
- 작성일: 2026-10-07

## 0. 사용자가 정한 것 (2026-10-07)

| 질문 | 답 |
|---|---|
| 나누는 방식 | **repo 구획 + 사이드바 연동** — 전체를 볼 때는 repo마다 접을 수 있는 구획, 사이드바에서 repo를 고르면 그 repo의 대화만 |
| 순서 | **최근 활동순** — 구획도, 구획 안도 |

## 1. 범위

렌더러만 바뀐다. core·IPC·스키마·마이그레이션 없음 — 대화의 repo는 이미 렌더러에 있는 `run.cwd`와 `repos`로 정한다.

**빠지는 것**: 인박스·배지(workspace 단위 그대로), 끝낸 대화 목록의 구획(거르기만 한다), repo 구획의 순서를 손으로 바꾸기.

## 2. 기능 요구사항

### (A) 대화의 repo

- **FR-1** 대화의 repo는 **뿌리 턴의 `cwd`**와 경로가 같은 등록 repo다. 이어 가는 대화는 작업 디렉토리를 바꿀 수 없으므로
  (작업 디렉토리 알약이 잠긴다) 뿌리 하나로 정해진다. 경로 비교는 끝의 `/`·`\`를 떼고, Windows 경로(드라이브 문자로 시작하거나
  `\`를 품은 것)는 대소문자를 가리지 않는다. 맞는 repo가 없으면(등록하지 않은 경로, 지운 repo) **기타**다.
- **FR-2** 목록 줄과 대화 헤더의 repo 이름(`repoLabel`)도 같은 판정을 쓴다 — 지금은 마지막 턴의 `cwd`를 정확히 일치로 본다.
  따로 두면 구획은 `api`인데 줄은 경로 끝 이름을 말하는 어긋남이 생긴다.

### (B) 구획

- **FR-3** 사이드바에서 repo를 고르지 않았을 때(전체) 끝나지 않은 대화를 repo 구획으로 나눈다. 구획은 repo 하나 + 맨 아래 `기타`
  하나(있을 때만). 구획 순서는 **그 구획에서 가장 최근에 활동한 대화**의 시각 최신순이고, `기타`는 늘 맨 아래다.
- **FR-4** 구획 안은 지금 목록 그대로다 — 최신순, 같은 이슈의 대화가 **그 구획 안에서** 둘 이상이면 이슈 한 줄로 접는다
  (`foldByIssue`를 구획마다 적용). 구획 안의 줄은 repo 이름을 메타에서 뺀다(구획 머리가 말한다).
- **FR-5** 구획이 하나뿐이면(전부 한 repo, 기타 없음) 머리 없이 지금 목록 그대로 그린다 — 머리 하나는 정보가 없다.
- **FR-6** 구획 머리: 꺾쇠 · repo 이름 · 대화 수 알약. 누르면 접고 편다(`aria-expanded`). 접힌 머리에도 그 구획에 **실행 중**이나
  **답변 필요**가 있으면 그 점을 머리 오른쪽에 보인다(이슈 줄과 같은 규칙). 접근성 이름은 `<repo> 대화 묶음`
  (`기타`는 `기타 대화 묶음`) — "접기/펼치기"를 이름에 넣지 않는다(CLAUDE.md의 부분 일치).
- **FR-7** 접힘은 사용자가 정한다 — 기본은 전부 펼침이고, 접은 구획은 이 장비에 repo id로 기억한다(localStorage, 보기 취향 —
  `listWidth.ts`와 같은 방식). 상태 전이나 새 대화로 펼쳐지지 않는다. **예외 하나**: `focusConversationId`(인박스·이슈 상세·리포트의
  "대화 열기")로 연 대화가 접힌 구획 안에 있으면 그 구획을 편다 — 이슈 줄을 펴는 지금 규칙(`revealIssueOf`)과 같다.

### (C) 사이드바 연동

- **FR-8** 사이드바에서 repo를 고르면 목록(끝나지 않은 것과 끝낸 것 둘 다)이 **그 repo의 대화만** 보인다. 구획 머리는 없다.
  목록 맨 위에 거름 줄이 선다: `api 대화만` + 풀기 버튼(이름 `repo 거름 풀기`). 풀기는 사이드바의 repo 선택을 푼다 — 이슈·메모
  패널의 거름도 같이 풀린다(앱의 repo 거름은 하나다).
- **FR-9** 거름은 **보기만** 바꾼다. 지금 열려 있는 대화가 거름 밖이어도 닫거나 바꾸지 않는다(입력부의 전송 대상이 조용히 바뀌면
  안 된다 — Dock의 `selected` 주석). 고른 적이 없을 때의 폴백(`openConversations[0]`)만 거른 목록에서 고른다.
- **FR-10** 거른 결과가 비면 `api에서 나눈 대화가 없습니다` 안내. 새 대화의 작업 디렉토리 기본값은 지금처럼 사이드바의 repo다.
- **FR-11** `Dock`에 필수 prop `onClearRepoFilter`가 더해진다(App이 `setRepoId(null)`) — 선택 prop이면 App의 한 줄을 지워도
  조용히 컴파일된다.

## 3. 비기능

- **NFR-1** 판정(대화의 repo·구획 나누기·순서·거름)은 `renderer/conversation.ts`의 순수 함수(`repoOfConversation`·
  `sectionByRepo`)다. 컴포넌트는 그리기만 한다.
- **NFR-2** 색은 토큰만. 구획 머리는 굵은 흐린 글자(0.6875rem 700, `--text-muted`) — 목록 줄과 무게가 갈린다. **대문자로 바꾸지 않는다**
  — repo 이름은 식별자라 `api`가 `API`가 되면 다른 이름처럼 읽힌다(캡처에서 정함).
- **NFR-3** 새 이름 `<repo> 대화 묶음`·`repo 거름 풀기`가 기존 e2e와 부분 일치로 부딪히지 않는지 전체 e2e로 본다.

## 4. 우려

1. repo 경로를 설정에서 바꾸면 옛 대화의 `cwd`는 옛 경로라 `기타`로 간다. run 행을 고치지 않는다(기록이다) — 받아들인다.
2. 사이드바 거름이 도크까지 거르면, 다른 repo의 대화가 답변을 기다려도 목록에서 안 보인다. 배지(workspace 단위)는 그대로 세고,
   거름 줄이 거르고 있다는 것을 늘 말한다.

## 5. 검증

- 단위: `repoOfConversation`(뿌리 cwd · 끝 구분자 · Windows 대소문자 · 없는 repo → 기타), `sectionByRepo`(구획 순서 · 기타 맨 아래 ·
  구획 안 이슈 접기 · 구획 하나면 머리 없음 · 거름).
- 컴포넌트(Dock.test): 구획 접기와 기억, 접힌 구획의 실행 중 점, 거름 줄과 풀기, 거름 밖의 열린 대화가 유지됨, focus로 연 대화의 구획이 펴짐.
- 배선(App.test): 사이드바 repo 선택 → 도크 거름, 풀기 → 사이드바 선택 해제.
- e2e: repo 둘에서 대화를 하나씩 돌려 구획 둘 → repo를 고르면 하나만 → 풀기.
- 실제 앱 캡처(라이트·다크).

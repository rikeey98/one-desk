# Spec: 로그인한 뒤에도 슬래시 커맨드 목록이 실패로 남는 결함

- 출처: `docs/backlog.md` §1 (2026-09-28). 원인이 알려진 결함이라 **intent는 따로 두지 않는다** —
  backlog 항목이 문제·원인·고칠 틈을 이미 적었다.
- 고치는 설계: `docs/sdlc/slash-commands/spec.md` FR-13, `docs/sdlc/agent-setup/` FR-1
- 작성자: 권용현 (초안: Claude)
- 상태: 구현 완료 (2026-09-28, 승인 2026-09-28)

## 1. 문제

로그인하지 않은 채 실행 패널을 열면 probe가 실패하고, `core/commands/service.ts`가 그 실패를
cwd마다 캐시한다(FR-13 — "실패도 수동 새로고침 전까지 유지"). 그 뒤 `claude auth login`을
마쳐도:

1. 실행 패널의 `/` 피커는 캐시된 실패를 계속 보여준다. 캐시를 비우는 길은 피커의
   `커맨드 새로고침`·앱 재시작뿐이고, 사용자는 로그인 때문이라는 것을 모른다.
2. 설정의 `다시 확인`(`core.workspaces.probeAgents(ws, true)`)은 **첫 repo의 cwd만** 비운다.
   실행 패널에서 다른 repo를 골랐다면 그 cwd의 실패가 남는다.

## 2. 요구사항

- **FR-1.** 설정의 `다시 확인`은 그 workspace에 등록된 **모든 repo의 cwd** 캐시를 비운다.
  모델 칸은 여전히 첫 repo에서만 probe한다(나머지는 비우기만 하고 띄우지 않는다 — 다음에
  그 cwd로 피커를 열 때 얻는다).
- **FR-2.** 실패한 probe를 캐시할 때 **그 순간의 claude 인증 상태**(`auth status`)를 함께 적는다.
- **FR-3.** 캐시된 실패를 돌려주기 전에(`list`·`agentInfo`), 적어 둔 인증 상태가 `ok`가 아니었으면
  인증을 다시 묻는다. 지금 `ok`이면 그 캐시를 버리고 다시 얻는다. 그 밖에는 캐시를 그대로 쓴다.
- **FR-4.** 인증이 `ok`인 채로 난 실패(훅 오류·타임아웃 등)는 지금처럼 새로고침 전까지 유지한다
  — 인증을 다시 묻지도 않는다. FR-13이 막으려던 "재마운트마다 `SessionStart` 훅이 도는 것"은
  그대로 막힌다. 인증 조회는 훅을 타지 않는다(agent-setup 실측 0.24초).
- **FR-5.** 성공한 결과에는 아무것도 더하지 않는다 — 인증을 묻지 않는다.
- **FR-6.** 인증 조회가 던지거나 `unknown`이면 "`ok`가 아니다"로 적고, 다음 조회에서도 `ok`가
  아니면 캐시를 쓴다. 인증 조회 실패로 목록 조회가 실패하지 않는다(slash-commands NFR-2).

**FR-13의 개정.** "실패도 수동 새로고침 전까지 유지"는 "**인증이 풀려 있어서 난 실패는 로그인이
확인되는 순간 버린다. 그 밖의 실패는 수동 새로고침 전까지 유지**"가 된다.
`docs/sdlc/slash-commands/spec.md` FR-13 아래에 이 개정을 한 줄 단다.

## 3. 비기능

- **NFR-1.** 마이그레이션·IPC 채널·렌더러 변경 없음. 바뀌는 것은 core의 커맨드 서비스와
  `probeAgents`뿐이다.
- **NFR-2.** 인증 판정은 `core/agent/auth.ts`의 `checkAuth` 한 곳을 쓴다 — 커맨드 서비스가
  `auth status`를 따로 구현하지 않는다(agent-setup NFR-3과 같은 이유).
- **NFR-3.** 로그인하지 않은 동안 피커를 열 때마다 `auth status`가 한 번 돈다(≈0.24초, 훅 없음).
  이 비용은 인증이 풀린 경우에만 생긴다.

## 4. 우려

1. **로그인 전 실패가 정말 probe 실패인가.** `system/init`은 인증을 보지 않는다(CLAUDE.md 실측).
   그런데 backlog의 증상은 "init이 계속 실패로 보인다"다. 원인이 인증이 아니라 그 시점의 다른
   무엇(훅·타임아웃)이었다면, 실패할 때 적어 둔 인증 상태가 `none`인 한 FR-3이 여전히 로그인 뒤
   한 번 다시 얻어 준다. 로그인과 무관한 실패는 FR-4대로 남는다. **어느 경우든 이 변경으로
   나빠지는 경로는 없다.**
2. **opencode는 대상이 아니다.** 피커가 claude 전용이다(slash-commands spec).

# Spec: 대화에 담는 버튼 — 줄 끝의 글자 버튼과 열린 항목의 헤더

- 출처: 사용자 요청(2026-11-05) — "이슈 메모 스킬을 대화에 넣는 방법이 왼쪽 동그라미 누르는건데 더 직관적으로 보이면 좋겠다.
  이슈 메모를 확대해서 볼 때는 그걸 대화에 적용시키려면 또 축소해야 해." 요청이 구체적이고 렌더러만 바뀌어 intent·plan은 두지 않는다.
- 작성자: 권용현 (초안: Claude)
- 상태: 구현 완료 (2026-11-05). §2의 선택은 뒤집을 수 있다.
- 마이그레이션·IPC·스키마 변경 없음.
- 뒤집은 결정: 2026-08-14 본문 설계 §5의 "담기 토글이 줄의 맨 앞이다 — 체크박스처럼 읽히도록".

## 1. 무엇이 문제였나

- 줄 맨 앞의 16px 빈 동그라미는 글자도 아이콘도 없어 눌러 보기 전에는 뜻을 알 수 없었다.
- 이슈 목록의 왼쪽 끝 체크는 다른 도구들에서 "완료 표시"의 자리다. 담은 줄이 파란 체크로 남으면 그 이슈가 끝난 것처럼 보인다.
- 항목을 열면 그 패널의 목록이 숨으므로(2026-09-22 결정) 열어 본 항목을 담는 길이 없었다. 닫고, 담고, 다시 열어야 했다.

## 2. 비교한 시안 (실제 앱 캡처)

| 안 | 모양 | 판단 |
|---|---|---|
| 왼쪽 ＋ 상자 | 자리는 그대로, `＋` → 파란 `✓` | 담기 전은 나아졌지만 담은 줄이 여전히 완료 체크로 읽혔다. 버렸다 |
| 줄 끝 글자 버튼 | `＋ 담기` → `✓ 담김`, 선택 칩의 색 | 고른 안. 글자가 하는 일을 말하고, 줄마다 약 34px을 더 쓴다 |
| hover에만 보이는 버튼 | 평소에는 없음 | "보이면 좋겠다"에 어긋난다. e2e 약 40곳의 `waitFor visible`도 깨진다. 버렸다 |
| 입력 카드의 `＋` 피커 | 대화 쪽에서 항목을 고른다 | 다른 기능이다. 이번 범위 밖 |

## 3. 동작

- **FR-1.** 이슈·메모·skill 줄의 맨 끝에 `＋ 담기`가 늘 보인다. 담기면 `✓ 담김`이고 다시 누르면 뺀다. 풍선은 누르면 일어날 일(`대화에 담기`/`대화에서 빼기`)을 말한다.
- **FR-2.** 버튼은 삭제(hover에 펼쳐진다)보다 뒤에 있다. 그래서 줄에 마우스를 올려도 움직이지 않는다.
- **FR-3.** 항목을 열면 패널 헤더의 축소 왼쪽에 `＋ 대화에 담기`가 선다. 담기면 `✓ 대화에 담김`이다. 축소하지 않고 담고 뺄 수 있고, 상세는 그대로 남는다.
  상세는 스크롤되지만 헤더는 남으므로 본문이 길어도 닿는다. 훑기 카드에서도 같다.
- **FR-4.** 항목을 연 동안 옆의 좁은 열(180px)에서는 글자가 사라지고 아이콘만 남아 제목이 자리를 갖는다.
- **FR-5.** 사이드바 repo 줄은 왼쪽의 아이콘뿐이다. 호버 동작이 오른쪽을 쓰고 사이드바에 글자를 둘 폭이 없다.
- **FR-6.** 지시 파일은 어느 자리에도 버튼이 없다(repo-instructions FR-8). 패널 창에도 없다(item-windows FR-8).

## 4. 이름

- 줄의 접근성 이름은 그대로 `<이름> 맥락에 담기`다. e2e 약 40곳이 이것으로 잡는다.
- 헤더의 이름은 `대화에 담기`이고 담겨도 바뀌지 않는다(`aria-pressed`가 상태를 말한다). 제목을 넣지 않는 것은, 상세가 열려도 목록이 DOM에 남아 단위 테스트에서 같은 이름이 둘이 되기 때문이다.

# Spec: git이 아닌 폴더의 코드 칸 — 폴더를 훑은 목록과 읽지 않는 이름 설정

- 뒤집는 결정: `docs/sdlc/code-editor/spec.md` §4의 1(파일 칸은 git repo만), `docs/sdlc/input-triggers/`의 "git이 아닌 repo에서는 `@`가
  아무것도 싣지 않는다"
- 작성자: 권용현 (초안: Claude)
- 상태: **초안** — 승인을 기다린다

## 0. 코드를 읽고 intent를 고친 것

1. **"git이 아니다"의 판정을 git의 오류 문구에서 파일 시스템으로 옮긴다.** intent는 "git이 그렇다고 말할 때만"이었다. 그런데 지금의 판정
   (`list.ts`의 `/not a git repository/i`)은 git의 메시지가 영어일 때만 맞는다 — git은 로캘에 따라 메시지를 번역한다. 그리고 git이 없는
   장비에서는 git이 아닌 폴더도 영영 비어 있게 된다(intent에서 대가로 적은 것). 대신 **root와 그 조상 어디에도 `.git`(폴더 또는 파일)이
   없으면 git이 아닌 폴더**로 본다(FR-1). git 자신이 저장소를 찾는 규칙과 같고(worktree·submodule은 `.git`이 파일이다), git을 띄우지 않고
   정해지므로 git이 없는 장비에서도 맞는다. `.git`이 있는데 git이 실패하면 지금처럼 이유를 보인다 — intent의 "git이 고장 나서 무시 규칙 없는
   목록으로 조용히 바뀌면 안 된다"는 그대로 지켜진다.
2. **훑은 목록 안의 `.git`은 설정과 무관하게 늘 뺀다.** git이 아닌 폴더 안에도 하위 폴더 하나가 git repo일 수 있다(`sub/.git`). 그 이름을
   사람이 설정에서 지우면 `sub/.git/hooks/*`를 쓰는 길이 열린다 — code-editor spec §3-4가 막으려던 바로 그것이다. 그래서 `.git`은 설정
   목록에 들지 않는 고정 규칙이다(FR-4).
3. **목록에 "있다"는 판정을 폴더 모드에서는 규칙으로 한다.** git 모드의 저장은 "새 목록에 있는 파일만"이다. 폴더 모드에서 같은 것을 하면
   저장마다 폴더 전체를 훑어야 하고, 상한에 걸려 잘린 목록이면 화면에 보이는(앞부분의) 파일이 아니라 뒷부분 파일의 저장이 실패한다.
   대신 경로 하나를 규칙으로 본다 — 구간마다 읽지 않는 이름이 아니고, 심링크·junction이 아닌 진짜 폴더·파일인가(FR-7). 훑기는 그 규칙을
   만족하는 경로를 늘어놓을 뿐이라 둘이 갈리지 않는다.

## 1. 현황

- 목록 함수 `listRepoFiles`(`core/files/list.ts`)의 결과 `RepoFileList`를 서비스(`core/files/service.ts`)의 다섯 메서드가 쓴다 — `tree`
  (트리), `open`(목록에 있는 것만), `save`(새 목록에 있는 것만), `search`(`@` 피커), `resolveMentions`(보낼 때).
- repo 밖 판정은 목록과 별개로 `read.ts`·`write.ts`가 양쪽 realpath로 한다. 이 spec은 그것을 건드리지 않는다.
- 목록은 repo 경로마다 10초 캐시(프로미스째)이고 실패는 캐시하지 않는다.
- 앱 설정은 `app_setting` 키-값이다(`core/db/repositories/setting.ts`). 글로벌 asset 경로가 같은 모양(한 줄에 하나, textarea)이다.

## 2. 요구사항

### 판정과 목록

- **FR-1 모드.** repo의 목록 모드는 둘이다 — `git`과 `folder`. root부터 파일 시스템 루트(WSL repo는 그 distro의 UNC 루트)까지 올라가며
  `.git` 항목(폴더든 파일이든)이 하나라도 있으면 `git`, 없으면 `folder`다. 판정은 목록을 얻을 때마다 새로 한다(캐시 안 — `git init`을 한
  뒤 다음 조회부터 git 모드가 돼야 한다). `stat` 몇 번이다.
- **FR-2 git 모드는 지금 그대로다.** `git ls-files -co --exclude-standard -z`, 실패하면 이유. 읽지 않는 이름 설정은 걸리지 않는다.
- **FR-3 folder 모드의 훑기.** root에서 너비 우선으로 내려간다(root에 가까운 파일이 먼저 — 잘려도 위쪽이 남는다). 항목마다:
  - 이름이 읽지 않는 이름(FR-4·FR-5)이면 폴더든 파일이든 건너뛴다. 폴더면 안을 읽지 않는다.
  - 진짜 폴더도 진짜 파일도 아니면(심링크, Windows junction, 장치 등 — `lstat` 기준) 건너뛴다. 따라가지 않는다.
  - 읽을 수 없는 폴더(권한)는 건너뛰고 계속한다.
  - 경로는 `/` 구분의 root 상대 경로다(git 모드의 모양과 같다).
- **FR-4 고정 규칙.** `.git`은 설정과 무관하게 늘 읽지 않는다(§0의 2). 설정 화면에 보이지 않고 지울 수 없다.
- **FR-5 이름 비교.** 이름 전체가 같을 때만 맞는다. 대소문자를 가리지 않는다(모든 플랫폼 — 한 규칙으로 둔다. Windows·macOS 기본 파일
  시스템이 가리지 않고, 리눅스에서 `Build`와 `build`를 갈라 쓸 사람은 드물다고 본다 — 추정). 와일드카드·경로는 없다.
- **FR-6 상한.** 개수는 `MAX_LISTED_FILES`(20만) 그대로. 시간은 10초다(git 조회의 5초보다 길다 — 디렉토리를 직접 읽고 WSL은 UNC를 탄다.
  plan에서 실제 폴더로 잰 뒤 정한다). 어느 상한이든 넘으면 그때까지 모은 것을 `truncated: true`로 돌려준다 — 버리지 않는다. 트리는 이미
  `truncated`를 보인다.
- **FR-7 목록에 "있다"의 판정.** 서비스의 `open`·`save`·`resolveMentions`가 "목록에 있는가"를 볼 때:
  - git 모드 — 지금 그대로(목록에 포함, `save`는 새 목록).
  - folder 모드 — 경로 규칙: 빈 구간·`.`·`..`가 없고, 구간마다 읽지 않는 이름이 아니며, root부터 각 구간이 `lstat`으로 진짜 폴더이고 끝이
    진짜 파일이다. 훑은 목록과 같은 규칙이라 잘린 목록에도 저장이 된다(§0의 3). 저장 직전에 **그때의** 설정과 그때의 디스크로 본다.
  - `resolveMentions`의 퍼지 매칭(`longestFileMatch`)은 훑은 목록을 그대로 쓴다 — 매칭은 목록이 필요하고, 고른 경로는 다시 규칙으로 본다.
- **FR-8 결과 모양.** `RepoFileList`·`FileTreeResult`의 성공에 `source: 'git' | 'folder'`가 붙는다(필수). 화면이 안내문을 고르는 재료다.

### 읽지 않는 이름 설정

- **FR-9 저장.** `app_setting`의 `files.skipNames`, 한 줄에 이름 하나. **행이 없으면 기본 목록**(FR-10), 행이 있으면 그 값이다 — 빈 값이면
  빈 목록이다(사람이 다 지운 것을 기본값으로 되돌리지 않는다. 글로벌 asset 경로의 "비우면 기본값"과 다른 것은 의도다 — 빈 경로 목록은 앱이
  쓸모없어지지만 빈 이름 목록은 "전부 보기"라는 뜻이 있다). 마이그레이션 없음.
- **FR-10 기본 목록.** `node_modules` · `bower_components` · `.hg` · `.svn` · `dist` · `build` · `out` · `target` · `coverage` · `.venv` · `venv` ·
  `__pycache__` · `.pytest_cache` · `.mypy_cache` · `.next` · `.nuxt` · `.turbo` · `.cache` · `.gradle` · `.DS_Store` · `Thumbs.db`.
  숨김 폴더를 통째로 빼지 않는다 — `.vscode`·`.claude`·`.github`는 보인다(intent 미해결 질문의 답).
- **FR-11 검증.** 저장할 때 줄마다 앞뒤 공백을 걷고 빈 줄을 버린다. `/`·`\`가 든 이름, `.`, `..`는 거부한다(오류 문구가 그 줄을 말한다 —
  경로를 넣으면 맞지 않는데 조용히 저장되면 "왜 안 빠지지"가 된다). 대소문자만 다른 중복은 하나로 접는다. `.git`을 적으면 받되 저장하지
  않는다(FR-4가 이미 뺀다) — 오류로 막을 이유가 없다.
- **FR-12 반영.** 저장하면 파일 서비스의 목록 캐시를 전부 비운다. 열린 트리는 다음 새로고침(2초 확인이 아니라 트리 조회 — 칸을 다시 열거나
  `파일 목록 새로고침`)부터 따른다. 이미 열린 편집기의 파일은 닫지 않는다 — 그 파일의 저장은 FR-7에 걸려 거부된다(이유를 보인다).
- **FR-13 화면.** 설정 **앱 탭**, `터미널 셸` 절과 `글로벌 asset 경로` 절 사이에 `폴더에서 읽지 않는 이름` 절.
  - 안내: "git이 아닌 폴더의 코드 칸 트리와 `@` 목록에서 뺄 이름입니다. 한 줄에 하나, 대소문자는 가리지 않습니다. git 저장소에는 걸리지
    않습니다 — 거기서는 `.gitignore`가 정합니다. `.git`은 늘 뺍니다."
  - textarea(이름 `읽지 않는 이름`), `기본값으로`(입력칸에 기본 목록을 채울 뿐 저장하지 않는다), `저장`(이름 `읽지 않는 이름 저장` —
    바뀐 것이 있을 때만 활성, 기존 규칙). 초안 state는 `SettingsPanel`이 쥔다(탭 전환 규칙).
  - 이름 충돌: `읽지 않는 이름`은 기존 라벨의 부분 문자열이 아니고 기존 라벨을 품지 않는다. `기본값으로`는 `기본값 저장`과 부분 일치하지
    않는다(plan에서 e2e로 확인).

### 코드 칸

- **FR-14 안내문.** `source: 'folder'`면 트리 위에 한 줄 — "git 저장소가 아니라 폴더를 그대로 보입니다 · 읽지 않는 이름은 설정의 앱 탭에서
  고칩니다". `--text-muted`, `role="note"`. git 모드에서는 서지 않는다.
- **FR-15 나머지는 같다.** 열기·저장(해시 충돌·줄바꿈·BOM·섞인 줄바꿈 읽기 전용)·2초 바뀜 확인·닫기 확인은 모드와 무관하다.

### `@` 파일 참조

- **FR-16** folder 모드에서 피커는 훑은 목록에서 고르고, 보낼 때의 해석은 훑은 목록 + FR-7 규칙이다. 읽기 거부(바이너리·크기·개수)는
  그대로다. 프롬프트의 `@` 중화(input-triggers FR-12)는 모드와 무관하다.

## 3. 범위 밖

- git repo에서 무시된 파일 보이기. repo마다 다른 이름 목록. 와일드카드·`.gitignore` 읽기. 지연 로딩(intent 그대로).
- 대화록 편집 줄의 `코드 칸에서 열기`가 folder 모드에서 읽지 않는 이름 안의 파일을 가리키는 경우 — 지금 무시된 파일과 같은 실패 문구로
  열지 않는다(문구만 모드에 맞게 — "읽지 않는 이름 안의 파일이라 열 수 없습니다").

## 4. 우려 (정해야 할 것)

1. **folder 모드에서는 `.env`가 트리와 `@`에 보인다.** git repo라면 무시됐을 비밀 파일이 화면에 뜨고 `@`로 고를 수 있다. intent는 "그 폴더의
   agent가 어차피 읽을 수 있다"로 받았다. 기본 목록에 `.env`를 넣으면 막을 수 있지만 그 파일을 고치러 온 사람은 설정을 바꿔야 한다. 이
   spec은 **넣지 않는다**. → **사용자**.
2. **조상에 `.git`이 있으면 git 모드다.** 홈 폴더 전체가 dotfiles git repo인 장비에서는 그 아래 모든 폴더가 git 모드가 되고, 그 repo의
   `.gitignore`가 `*`라면 트리가 빈다. git 자신이 그렇게 보므로 맞는 판정이라고 본다. 증상이 보고되면 그때 다시 본다.
3. **거대한 폴더.** 드라이브 루트나 홈을 등록하면 10초·20만 개 상한까지 훑는다 — 그동안 트리는 "불러오는 중"이고 메인 프로세스는 막히지
   않는다(비동기 `fs/promises`). 매 조회마다 반복되므로 10초 캐시가 끝날 때마다 다시 10초다. plan에서 홈 폴더로 재 본다. 너무 느리면
   folder 모드만 캐시를 길게(예: 60초) 두는 것을 plan에서 정한다.
4. **FR-5의 대소문자 무시는 리눅스에서 드물게 틀린다.** `Build/`가 소스인 프로젝트는 그 폴더가 빠진다. 설정에서 `build`를 지우면 풀린다.

## 5. 성공 기준

intent의 기준에 더해:

- 단위: 조상에 `.git` 파일(worktree 모양)이 있으면 git 모드, 없으면 folder 모드. git 실행 파일이 없어도 folder 모드 목록이 선다.
- 단위: folder 모드 안의 `sub/.git/hooks/pre-commit`은 설정을 비워도 목록에 없고 `save`가 거부한다.
- 단위: 잘린 목록(상한을 작게 주입)에 없는 뒷부분 파일도 규칙에 맞으면 `save`가 된다. junction/심링크 안의 파일은 거부한다.
- 단위: 설정 저장이 캐시를 비운다 — 저장 직후의 `tree`가 새 이름을 따른다.
- e2e: git이 아닌 임시 폴더를 repo로 등록 → 안내문 · `node_modules` 없음 · 열고 저장(디스크 바이트) · `@`로 실림 · 설정 앱 탭에서 이름을
  더하고 트리 새로고침하면 그 폴더가 사라짐.
- 기존 `code-pane.e2e`(git repo)와 `.gitignore` 테스트가 그대로 초록.

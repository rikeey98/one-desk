# Spec: 이슈·메모를 내용부터 쓴다 — 첫 줄이 제목

- 작성자: 권용현
- 상태: 승인됨 (2026-10-03) — 개발 버전(`exp/conversation-issue`)에 같이 넣어 써 본다
- 작성일: 2026-10-03

## 1. 문제

2026-10-03 사용자(요약): "새 이슈를 만들 때 제목부터 쓰기가 어렵다. 내용부터 쓰는 게 편하다."

추가 칸이 `새 이슈 제목…` 한 줄이라 제목을 먼저 지어야 만들어진다. 머릿속에 있는 것은 보통 "무슨 일이 있었나"이지 요약된
제목이 아니다. 이슈 훑기 설계가 정한 원칙("던질 땐 최소한만 — 축을 요구하는 순간 회의 중에 못 던진다",
`2026-08-27-issue-triage-design.md`)과 같은 종류의 마찰이다.

제목을 비워 두는 길은 택하지 않는다. 제목은 목록 줄·훑기 카드·**대화 제목**(할당된 이슈, `docs/sdlc/conversation-issue/`
FR-22)·MCP `list_issues`(본문을 빼고 제목만 준다)가 본다.

## 2. 기능 요구사항

- **FR-1.** 이슈·메모의 추가 칸은 여러 줄이다. **첫 줄이 제목, 나머지가 본문이다**(Apple 메모 방식). 한 줄만 쓰면 지금처럼
  제목만 있는 항목이다. 규칙은 순수 함수 `renderer/titleBody.ts`의 `splitTitleBody` 하나다.
  - 첫 줄이 길어도 자르지 않는다 — 자르면 글이 잘리거나 본문에 같은 글이 두 번 들어간다. 목록은 말줄임으로 보인다.
  - 첫 줄 앞의 마크다운 제목 표시(`# `~`###### `)는 뗀다. 표시만 있는 줄(`#해시태그`)은 그대로다.
  - 본문 앞의 빈 줄은 걷고, 본문 안의 줄바꿈·들여쓰기는 그대로다. CRLF도 줄로 가른다.
- **FR-2.** **Enter는 만들기, Shift+Enter는 줄바꿈이다.** 한 줄로 던지던 습관(제목 + Enter)과 기존 e2e가 그대로 간다. 한글
  조합 중의 Enter는 글자 확정이라 만들지 않는다(`isComposing`). 입력부(Ctrl/⌘+Enter 전송)와 키가 다른 것은 받아들였다 —
  입력부는 긴 지시를 쓰는 곳이고 여기는 던지는 곳이다.
- **FR-3.** 칸은 한 줄 높이에서 시작해 쓰는 만큼 늘어나고(`field-sizing: content`) 200px에서 멈춘다. `+` 표시는 첫 줄 옆에
  남는다. 키 안내는 칸의 `title`이다(`Enter로 만들기 · Shift+Enter로 줄바꿈 — 첫 줄이 제목이 됩니다`).
- **FR-4.** placeholder는 `새 이슈 (첫 줄이 제목)` · `새 메모 (첫 줄이 제목)`다. e2e가 placeholder로 칸을 잡으므로(7개 파일)
  같이 바꿨다.
- **FR-5.** **이슈와 메모가 대칭이다** — 제목·본문은 대칭으로 유지하는 공통 필드다(CLAUDE.md "의도된 중복"). 이름 칸
  (workspace·asset)은 한 줄 그대로다 — `AddForm`의 `multiline`은 선택이고 이슈·메모 패널만 켠다.
- **FR-6.** 본문이 비었으면 `create`에 `body`를 싣지 않는다 — 지금과 같은 요청이다.

## 3. 빠지는 것

- **agent가 제목을 지어 주는 것.** 앱은 CLI 실행 밖에서 모델을 부르지 않는다. MCP `update_issue`에 제목 칸도 없다. 첫 줄
  규칙으로 먼저 써 보고, 제목 짓기가 여전히 부담이면 다시 본다.
- **만들고 나서 상세를 바로 여는 것.** 지금처럼 목록에 더해질 뿐이다.

## 4. 우려

1. **첫 줄이 문장이면 제목이 길다.** 상세에서 고친다. 써 보고 자주 그러면 "첫 문장까지"나 길이 상한을 다시 본다.
2. **패널 창에서도 같은 칸이다.** 창은 같은 패널 컴포넌트를 그리므로 따로 할 일이 없다.

# Spec: 펼쳐도 목록이 보이게 — 옆 패널은 레일로

- 출처: 사용자 요청(2026-11-24) — "지금 아쉬웠던 부분은 확장하면 리스트를 못본다는점이야. 차라리 확장하면 다른 항목은 안보이게
  할까 아주 작게 축소시키고". 배치 셋을 실제 앱에 CSS만 입혀 찍어 비교한 뒤 "가 레일로"를 골랐다. 요청이 구체적이고 렌더러만
  바뀌어 intent·plan은 두지 않는다.
- 작성자: 권용현 (초안: Claude)
- 상태: 구현 (승인 대기). §3의 FR-3은 뒤집을 수 있다.
- 마이그레이션·IPC·스키마 변경 없음.
- 뒤집은 결정: 2026-09-22 "항목을 열면 그 패널이 남는 폭을 다 쓰고, 나머지 둘은 180px 목록 열로 옆에 남는다. 열린 패널 안에는
  상세만 남는다." context-pick FR-4("옆의 좁은 열에서는 아이콘만")는 그 열이 없어져 해당이 없다.

## 1. 무엇이 문제였나

- 항목을 열면 그 패널의 목록이 숨었다. 이슈를 하나씩 훑으려면 열고, 닫고, 다음을 여는 일을 되풀이해야 했다.
- 대신 옆 두 패널은 180px 목록으로 남아 있었다. 열어 둔 이슈와 상관없는 메모 목록이 이슈 목록보다 잘 보였다.

## 2. 비교한 시안 (실제 앱에 CSS만 입혀 찍음, 1440×900)

| 안 | 모양 | 펼친 패널 안 | 판단 |
|---|---|---|---|
| 가 · 레일 | 옆 둘을 44px 세로 막대로 접고 이름과 개수만 남긴다 | 목록 300px + 상세 약 720px | 고른 안 |
| 나 · 다른 둘 숨김 | 옆 둘이 사라진다 | 목록 300px + 상세 약 830px | 2026-09-22에 숨겨 봤다가 "다른 패널에 뭐가 있는지 안 보여 답답하다"로 되돌렸다 |
| 다 · 180px 열 유지 | 지금 배치에 목록만 더한다 | 목록 220px + 상세 약 530px | 가장 작은 변화지만 상세가 좁다 |

캡처는 디자인 캔버스 https://claude.ai/artifact/B83yrnJJTvbbchYVSxWrj9 의 "이슈·메모 모습" 페이지 맨 아래 줄에 있다.

## 3. 동작

- **FR-1.** 이슈·메모를 열면 그 패널 안에 목록(300px)과 상세가 나란하다. 열린 항목은 목록에서 파랗게 보인다. 처음에는 목록을
  제목만 남겼다(`.item-meta`를 숨김 — 300px에서 칩이 제목 옆에서 세로로 쌓여 제목이 잘렸다). 같은 날 `docs/sdlc/item-look/`이 표식을
  제목 아래 줄로 옮기면서 숨김을 걷었다 — 지금은 펼친 목록도 두 줄이다(그 spec FR-6).
- **FR-2.** 나머지 두 패널은 44px 레일이다. 세로로 쓴 이름과 개수만 보이고 헤더의 동작(새 창으로 열기 등)은 없다. 접근성 이름은
  `<패널> 보기`, 개수는 `aria-description`이다(보이는 수를 `aria-label`로 가리지 않는다).
- **FR-3.** 레일을 누르면 열린 항목을 닫고 세 패널로 돌아간다 — 축소 버튼과 같다. 그래서 이슈를 연 채로 메모를 바로 여는
  길은 없어졌다. 레일을 누르고 메모를 누르는 두 번이다. 다른 길("그 패널을 펼쳐 목록만 보인다")은 "항목 없이 펼친 패널"이라는
  새 상태가 필요해 하지 않았다. Esc와는 한 가지가 다르다 — 상세 안에서 누른 Esc는 대기 중인 저장을 먼저 흘려보내고 충돌이면
  닫지 않는데, 레일과 축소는 곧바로 닫는다(닫히며 언마운트 흘려보내기는 돈다. 충돌 배너는 말없이 사라진다 — 축소의 기존 한계).
- **FR-3a.** 레일에 포커스가 있었으면(키보드로 눌렀거나 레일에 둔 채 Esc) 레일이 사라져도 포커스가 body로 떨어지지 않고 돌아온
  패널(`section`, `tabIndex=-1`)로 간다. 다음 Tab은 그 패널 안에서 이어진다. 독립 리뷰가 찾았다.
- **FR-4.** 레일이어도 패널 본문은 언마운트하지 않는다(`hidden`). 추가 칸에 쓰던 글이 펼치면 그대로 있다.
- **FR-5.** 펼친 패널의 본문이 760px보다 좁으면(창이 좁거나 확대) 목록을 접고 상세만 남긴다 — 2026-11-24 전의 모양이다.
  창 폭 1280px 아래에서 옆 둘을 숨기던 규칙은 없앴다. 레일은 그 폭에도 들어간다.
- **FR-6.** 패널 창(item-windows)은 바뀌지 않는다. 패널이 하나라 늘 `normal`이고 목록·상세는 `WindowSplit`이 둔다.

## 4. 데이터 모양

`Panel`의 필수 prop `mode: PanelMode`가 `expanded: boolean`을 대신한다.

```ts
type PanelMode =
  | { kind: 'normal' }
  | { kind: 'expanded' }
  | { kind: 'rail'; onRestore: () => void }
```

레일은 늘 돌아갈 길을 들고 다닌다 — "레일인데 누를 곳이 없는" 상태를 만들 수 없다. 모양은 App의 `panelModeOf` 한 자리가
`openItem`에서 정한다(없으면 셋 다 `normal`, 있으면 그 패널만 `expanded`, 나머지는 `rail`).

## 5. 남은 것

- **스킬 / 에이전트는 펼쳐도 상세가 목록을 대신한다.** 이슈·메모처럼 나란히 두려면 `AssetPanel`의 펼친 모양과 스크롤 칸을 바꿔야 하고
  `e2e/asset.e2e.ts`의 스크롤 검사(`.panel-expanded .panel-body`)가 그것에 기댄다. 이번에는 하지 않았다.
- 펼친 패널 안 목록의 폭 조절은 없다. 패널 창의 `목록 폭 조절`을 앱 창에 들일지는 써 보고 정한다.
- ~~펼친 목록에서 숨기는 `.item-meta`에 상태 배지와 방치 ⚠도 들어 있다~~ — `docs/sdlc/item-look/` FR-6이 표식을 둘째 줄로 옮겨
  숨김을 걷었다. 펼친 목록에서도 나머지 줄의 상태가 보인다.

## 6. 검증

- 단위: `Panel.test`(레일 버튼과 콜백, 본문 유지, 보통·펼침에는 레일 없음), `App.test`의 "항목을 열면 나머지 두 패널은 레일로
  접히고, 레일을 누르면 세 패널로 돌아온다". 변이 둘 — App이 넘기는 `onRestore`를 빈 함수로, `Panel`이 레일일 때 본문을 그리지
  않게 — 각각 그 테스트를 빨갛게 했다.
- e2e: `e2e/panel-collapse.e2e.ts`의 "펼치면 목록이 상세 옆에 남고 다른 둘은 레일로 접힌다" — 목록과 상세의 위치, 레일 폭,
  키보드로 레일을 누르면 세 패널이 되고 포커스가 메모 패널에 간다, 1000×700 창에서는 상세만. jsdom이 레이아웃을 못 재므로 CSS는
  여기서만 지켜진다. 포커스를 옮기는 줄을 지우면 이 e2e가 빨개진다(실측). 전체 e2e 93개가 통과했다(선택 실행 4개는 건너뜀).
- 독립 리뷰(다른 에이전트, 변경을 쓰지 않은 쪽)를 한 번 돌렸다. 고친 것은 FR-3a, 기록만 한 것은 FR-3의 Esc 차이와 §5의 `.item-meta`.

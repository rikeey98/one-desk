# Intent: 대화의 수명 주기와 정체성

- 작성자: 권용현
- 상태: 승인됨 (2026-09-23)
- 작성일: 2026-09-23

## 문제

**대화가 끝나지 않는다.** 2026-09-23 사용자 요청(요약): "workspace 쪽 빨간 원의 숫자가
의미가 무색하다 — 대화 종료가 없어서 대화 수만큼 늘어나고, 인박스에 가서 확인함을 눌러야
내려간다. 대화 세션들이 가로로 쭉 있어 보기 어렵다. 세션 제목이 첫 지시라 무슨 세션인지
알기 어렵다."

증상이 셋이지만 뿌리는 하나다. **대화는 저장되지 않는 파생값이라 수명 주기도 정체성도
없다** — `renderer/conversation.ts`의 `groupConversations`가 run 목록을 `rootRunId`로 묶어
매 렌더 새로 만들 뿐, "이 대화는 끝났다"도 "이 대화는 무엇에 관한 것이다"도 어디에도
적히지 않는다. 그래서 대화를 세는 것(배지)도, 늘어놓는 것(도크 탭)도, 부르는 것(제목)도
전부 단조 증가하거나 무의미해진다.

### 1. 배지가 "손이 필요한 것"이 아니라 "지금까지 한 대화"를 센다

`run.ts`의 `inboxCounts()`는 **뿌리에 `reviewedAt`이 안 찍힌 대화**를 센다. `inbox.ts`의
카테고리 다섯 중 `done`(완료·미확인)도 그대로 들어간다 — 성공적으로 끝나 도크에서 답을
눈으로 읽은 대화조차 인박스에 가서 손으로 내려야만 배지에서 빠진다. 3b 설계 §5가 인박스를
"지금 사용자의 손이 필요한 대화"로 규정했는데 실제 동작이 그것보다 넓다.

run이 일회용이던 시절에는 이 넓이가 맞았다. 한 번 돌리고 끝나는 헤드리스 실행은 결과를
누군가 확인해야 했다. 그러나 대화(`2026-08-18-conversation-design.md`)가 붙으면서 run은
**계속 이어지는 채팅**이 됐고, 사용자는 그것을 도크에서 실시간으로 보고 있다. 이미 본 것을
다른 화면에 가서 다시 확인하라는 요구가 남은 것이다.

### 2. 도크 탭이 workspace의 모든 대화를 가로로 늘어놓는다

`useRuns`는 `runs.list(workspaceId)`를 부르고 그 쿼리에는 **개수 제한이 없다.** 그
workspace에서 지금까지 만든 모든 run이 온다. `Dock`이 그것을 대화로 묶어 전부 탭으로
그리고, `.dock-tabs`는 `overflow-x: auto` + `white-space: nowrap`이다. 대화가 서른 개면
가로 스크롤 서른 칸이고, **탭을 닫는 방법이 없다.**

### 3. 제목이 첫 지시의 첫 줄이다

`titleOf(run)`은 첫 턴 `userPrompt`의 첫 줄을 24자로 자른다. "이거 좀 봐줘"나 "다음 파일을
확인해:"가 그대로 제목이 된다. 탭이 좁고(`nowrap`) 여럿이라 이 제목만으로 원하는 대화를
찾는 것이 사실상 불가능하다.

## 현황 (읽고 확인한 것)

- **배지 = 미확인 대화 수.** `inboxCounts()`는 `unreviewedRootIds()` → `lastTurnsOf()`로
  대화마다 마지막 턴을 고르고 `INBOX_STATUSES`로 거른 뒤 세기만 한다. 카테고리를 보지
  않는다. `needsAnswer` 컬럼은 지금 select에 없다 — 1-A를 하려면 한 칸 더 읽어야 한다.
- **"확인 표시를 지우는 자리"는 이미 있다.** `create()`가 `parentRunId`를 받으면 뿌리의
  `reviewedAt`/`reviewedKind`를 지운다(`run.ts:324`). 즉 **자동 확인의 반대쪽 절반이
  공짜다** — 자동으로 내려도 새 턴이 오면 다시 뜬다. CLAUDE.md가 경고하는 "찍는 자리와
  지우는 자리는 항상 짝"이 이미 성립해 있다.
- **찍는 자리는 뿌리여야 한다.** `execution.cancel()`이 이 자리에서 한 번 걸렸다(C-1-a).
  `App.tsx`의 `reviewConversation`이 `conversationIdOf(run)`으로 변환해 넘긴다.
- **`Dock`의 폴백이 마운트만으로 대화를 고른다.** `pickedId`가 null이면
  `conversations[0]`이 selected가 된다. **자동 확인을 selected에 걸면 도크를 열기만 해도
  최근 대화가 조용히 내려간다** — 명시적 선택에만 걸어야 한다.
- **`markReviewed`는 이미 확인된 run의 시각을 덮어쓰지 않는다**(`isNull(run.reviewedAt)`
  조건). 자동 확인이 반복돼도 첫 시각이 보존된다.
- **`run.kind`류의 CHECK 제약과 달리 새 컬럼은 마이그레이션이 필요하다.** 지금 최신은
  `0007`이므로 `0008`이 된다. `root_run_id`를 NOT NULL로 만들 수 없는 것과 같은 이유로
  **테이블 재생성은 절대 하지 않는다** — `DROP TABLE run`이 `run_context_item`의 cascade를
  태운다. 컬럼 추가(`ALTER TABLE ADD COLUMN`)만 한다.
- **대화의 파생 속성이 모이는 곳은 `renderer/conversation.ts` 하나다.** `conversationIdOf`·
  `titleOf`·`groupConversations`·`contextOf`가 모두 여기 있고, `contextOf`는 이미 대화가
  지금까지 담은 맥락의 합집합을 준다 — **제목을 맥락에서 파생시킬 재료가 이미 있다.**
- **도크 높이는 사용자가 드래그로 늘린다**(`dockHeight.ts`). 세로 목록이 좁다는 약점을
  사용자가 스스로 풀 수 있다.
- 취소 버튼은 지금 헤더의 탭 스트립 안에 있다(`.dock-cancel`). 레이아웃을 바꾸면 이것도
  옮겨야 한다.

## 원하는 결과

- **빨간 원은 행동을 요구하는 것만 센다.** 답변 필요·실패·중단됨. 성공적으로 끝난 대화는
  배지를 올리지 않는다.
- **본 대화는 저절로 내려간다.** 도크에서 대화를 열어 읽으면 인박스에서 빠진다. 단
  답변 필요·실패는 예외다 — 열어 본 것과 처리한 것이 다르다.
- **대화를 끝낼 수 있다.** 끝낸 대화는 도크 목록에서 사라지고 다시 올라오지 않는다.
- **대화 목록이 세로다.** 제목 전체가 보이고, 어느 repo인지·언제인지·몇 턴인지가 함께
  보인다. 휠로 스크롤된다.
- **제목으로 대화를 알아본다.** 담은 맥락에서 제목이 나오고, 마음에 안 들면 이름을 바꾼다.

## 영향 범위

- **사용자**: 이 앱을 쓰는 모든 사람(현재 한 명, 작성자). 대화를 여러 개 굴리는 사람일수록
  크게 체감한다.
- **시스템**:
  - `core/db/schema.ts` + `drizzle/0008` — 대화의 저장 속성(제목·종료 시각). **컬럼 추가만.**
  - `core/db/repositories/run.ts` — `inboxCounts()`의 판정, 종료·이름 변경 메서드,
    `list()`가 종료된 대화를 어떻게 다룰지.
  - `core/index.ts` + IPC + preload + `shared/client.ts` — 새 통로 두엇.
  - `renderer/conversation.ts` — 제목 폴백, 종료된 대화 필터.
  - `renderer/components/Dock.tsx` + `index.css` — 헤더 탭 스트립 → 세로 목록. 취소 버튼과
    슬롯 표시기의 자리가 함께 바뀐다.
  - `renderer/components/InboxPanel.tsx` — `done`이 배지에서 빠진 뒤의 목록 동작.
  - `e2e/conversation.e2e.ts` — 도크 탭을 텍스트로 잡는 곳이 전부 바뀐다.
- **건드리지 않는 것**: 어댑터·권한·큐·MCP 도구·실행 파이프라인. 대화를 묶는 규칙
  (`rootRunId` 승계)도 그대로. 대화당 예약 하나(`groupKey`)도 그대로.

## 제약

- `core/`는 `electron`을 모르고, `renderer/`는 `core/`를 모르며, IPC 핸들러는 얇다.
- **`run` 테이블을 다시 만들지 않는다.** `ALTER TABLE ADD COLUMN`만.
- **인박스 판정은 뿌리(root run)에 찍는다.** 턴 id에 찍으면 아무 일도 일어나지 않는다.
- **찍는 자리를 늘리면 지우는 자리도 함께 본다.** 자동 확인·종료를 더할 때마다 "무엇이
  이것을 되돌리는가"를 명시한다.
- **끝낸 대화의 기록은 지우지 않는다.** 화면에서 내릴 뿐이다(사라진 asset을 지우지 않는
  것과 같은 원칙, 전체 설계 §232).
- 색은 `:root` 토큰에서만. 아이콘은 `icons.tsx`에서만. 안내문을 `opacity`로 흐리지 않는다.
- 짧은 라벨을 새로 붙이면 기존 e2e의 부분 일치가 깨진다 — 새 라벨은 e2e를 먼저 돌려 본다.

## 성공 기준

- 성공으로 끝난 대화를 도크에서 열어 읽으면 **인박스에 가지 않고도** 배지가 줄어든다.
  그 대화에 새 턴을 보내면 다시 오른다.
- 답변 필요로 멈춘 대화는 열어 봐도 배지에 남는다.
- 대화 스물을 만들어도 도크에 가로 스크롤이 생기지 않는다. 끝낸 대화는 목록에 없다.
- 이슈를 담아 시작한 대화의 제목이 그 이슈 제목이다. 이름을 바꾸면 그 이름이 남는다.
- `pnpm test` · `pnpm typecheck` · `pnpm lint` · `pnpm test:e2e` 전부 통과.
- 기존 DB를 열면 마이그레이션 `0008`이 한 번 돌고, 그전 대화들이 그대로 보인다.

## 결정 (2026-09-23, 사용자 — 브레인스토밍에서 선택)

- **배지에서 `done`을 뺀다** (1-A). 빨간 원은 답변 필요·실패·중단됨만.
- **본 대화는 자동으로 확인됨** (1-B). 답변 필요·실패는 제외.
- **도크 본문을 좌우로 갈라 왼쪽에 세로 대화 목록** (2-A).
- **대화 종료를 더한다** (2-D). `reviewedAt` 재사용이 아니라 별도 컬럼.
- **제목은 3단 폴백** — 사용자가 붙인 이름 > 담긴 맥락에서 파생 > 첫 지시의 첫 줄 (3-A+3-B).

## 미해결 질문 (해소됨, 2026-09-23 사용자)

- [x] **끝낸 대화를 다시 볼 수 있는가?** → **목록 하단에 "끝낸 대화" 토글.** 접힌 절로
      남고 펼치면 열 수 있다. 화면에서 내릴 뿐 기록을 지우지 않는다는 제약과 맞는다.
- [x] **끝낸 대화에 턴을 보내면?** → **종료가 풀린다.** 토글로 펼쳐 열 수 있으므로 보낼
      길이 있고, `create(parentRunId)`가 뿌리의 `reviewedAt`을 지우는 바로 그 자리에서
      `closedAt`도 함께 지운다 — 찍는 자리와 지우는 자리가 하나로 모인다.
- [x] **종료가 확인도 겸하는가?** → **겸한다.** 같은 트랜잭션에서 `reviewedAt`도
      찍는다(`kind: 'archived'`). 겸하지 않으면 끝낸 대화가 배지에 남아 종료의 의미가 없다.
- [x] **자동 확인의 발동 조건.** → **목록에서 대화를 명시적으로 눌렀을 때.** `Dock`의
      폴백(`conversations[0]`)이 원천적으로 걸리지 않고, 테스트로 고정하기도 쉽다.
- [x] **맥락 파생 제목의 형태.** → **첫 이슈/메모 제목 + 나머지 개수**(예: `로그인 깨짐 +2`).
      이슈·메모가 주제를 담고 repo·asset은 배경이므로 우선순위를 둔다. 이슈도 메모도
      없으면 repo 이름, 그것도 없으면 첫 지시의 첫 줄.
- [x] **중단됨(`interrupted`)이 배지에 남는 것.** → **남는다.** 앱이 꺼져 끊긴 것이라
      사람이 다시 돌릴지 정해야 한다. 오래된 것은 종료로 내린다.

## 남은 질문 (Design에서 다룬다)

- [ ] **도크 목록의 상한.** `runs.list`에 제한이 없다. 종료로 줄어들지만 끝내지 않고
      방치한 대화는 계속 쌓인다. 세로 스크롤로 버틸지, 상한을 둘지.
- [ ] **취소 버튼의 자리.** 지금은 헤더의 탭 스트립 옆이다(`.dock-cancel`). 탭 스트립이
      사라지면 옮겨야 한다 — `Transcript`의 턴별 취소는 `pending`에만 있어 `running`을
      덮지 못한다.

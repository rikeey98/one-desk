  첫째·둘째 줄의 다른 컨셉(A 대화 중심 · B IDE 탐색기 · C 흐름 보드 · D 집중 피드)은 **고르지 않았다** — 기존 구조를 바꾸지 않는
  E만 들인다.

## 정해진 것 (2026-10-21, 사용자)

- **기존 화면은 그대로 두고 첫 화면 하나를 더한다.** 사이드바 맨 위 `홈`(인박스 위). workspace 화면·인박스·리포트·설정은 바뀌지 않는다.
- **홈은 숫자판이 아니라 "오늘 할 일"이다.** 줄마다 버튼이 하나이고(답하기 · 다시 보내기 · 훑기 · 보기 · 대화 열기), 끝나면 줄이 빠진다.
- **홈은 workspace를 넘는다** — 인박스·리포트와 같은 층위다.
- **처음 켰을 때는 준비 단계 넷**(워크스페이스 → repo → CLI 확인 → 첫 대화)이 그 자리에 선다.

## 문제

앱을 열면 마지막으로 보던 workspace 화면이 뜬다. 그 화면은 **지금 고른 workspace · repo 하나**의 이슈·메모·대화뿐이라, 다른
workspace에서 agent가 답을 기다리고 있어도 사이드바 배지의 숫자 하나로만 안다. 배지를 누르면 인박스인데, 인박스는 **대화만**
센다 — 훑기를 기다리는 이슈(`triagedAt IS NULL`)와 오래 안 본 이슈(`seenAt`, 이슈 패널의 `⚠ 오래 방치됨`)는 그 workspace를 골라
이슈 패널을 봐야 드러난다. 그래서 아침에 앱을 켜고 "무엇부터 하나"를 알려면 workspace를 하나씩 돌아야 한다.

두 번째 문제는 **첫 실행**이다. 지금은 빈 사이드바와 빈 패널 셋이 뜨고, 무엇을 먼저 해야 하는지(workspace 만들기 → repo 등록 →
CLI 로그인)를 화면이 말하지 않는다. CLI가 로그인돼 있지 않다는 것은 설정 → 실행 탭까지 가야 보인다.

세 번째는 작은 창이다. 1280px 아래에서는 패널 둘이 숨고(CLAUDE.md "항목을 열면…"), 1100×760 노트북 창에서는 workspace 화면이
갑갑하다. 한 열로 쌓이는 화면이 하나도 없다.

## 원하는 결과

앱을 열면 **홈**이 뜬다. 1440×900 기준 위에서 아래로:

1. **지금 돌고 있는 것** — 실행 중인 대화(여러 개면 전부)와 예약·대기 수, 실행 슬롯. 줄마다 `대화 열기`·`멈추기`. 비어 있으면
   "돌고 있는 대화 없음" 한 줄.
2. **오늘 타임라인** — workspace마다 한 줄, 오늘의 대화를 시간 위에 막대로(완료·답변 필요·실행 중 색), 빨간 선이 지금. 리포트의
   요일 보드(period-report FR-17)를 하루로 줄인 것.
3. **오늘 할 일** — workspace를 넘어 한 목록. 종류는 섞이되 **줄마다 버튼 하나**:
   - 답변 필요 대화 → `답하기` (그 대화를 열고 입력칸에 포커스 — 대화록의 "답하기"와 같다)
   - 실패·중단된 대화 → `다시 보내기` (`runs.resume`) + `대화 열기`
   - 정리 안 된 이슈 (workspace마다 한 줄로 묶어 개수) → `훑기` (그 workspace의 훑기 화면)
   - 오래 안 본 이슈 (workspace마다 한 줄로 묶어 개수) → `보기` (그 workspace 이슈 패널, 방치 순)
   끝나면(답했다, 다시 보냈다, 훑었다, 열어 봤다) 줄이 빠진다. 이 목록의 수가 사이드바 `홈`의 배지다 — 인박스 배지(대화만)와
   **다른 수**이고 그것이 의도다.
4. **workspace 카드** — workspace마다 열림·진행 중·오늘 완료와 repo별 한 줄(대화 상태 점). 누르면 그 workspace 화면.
5. **오늘 완료**와 CLI 상태 한 줄(로그인·모델).
6. **바닥의 입력 카드** — 새 대화. 대상은 **마지막으로 대화를 보낸 workspace · repo**이고 알약을 눌러 바꾼다. 보내면 그 workspace
   화면의 도크로 옮겨 간다(지금의 `focusConversationId`).

**노트북 창(1100×760)** 에서는 사이드바가 접히고(지금의 `collapsed`) 같은 내용이 한 열로 쌓인다 — 타임라인은 숨긴다.

**처음 켰을 때**(workspace가 없거나, repo가 없거나, 어느 CLI도 준비되지 않았거나, 대화를 보낸 적이 없으면) 1~6 대신 준비 단계 넷이
선다. 끝난 단계는 한 줄로 접히고, CLI 칸은 설정 화면의 세 칸 판정(agent-setup FR-1 — 실행 파일 · 인증 · 모델)을 **그대로** 쓴다.
넷이 끝나면 다음 실행부터 1~6이다. 오른쪽에 "이 앱이 하는 일" 세 줄과 단축키 넷.

## 영향받는 것

- 사람: 여러 workspace를 오가는 사용자(회사 일·개인 프로젝트), 그리고 처음 설치한 사용자.
- 데이터: 읽기만 한다 — `run`(실행 중·답변 필요·실패·중단, 오늘의 턴 시각), `issue`(`triaged_at`·`seen_at`·`status`·`closed_at`),
  workspace·repo 목록, 앱 설정(마지막으로 보낸 workspace · repo — 지금은 없다, 아래 미해결). **스키마 변경 없음**(가정).
- 코드: workspace를 넘는 읽기는 `core.reports.build`처럼 **core에 한 자리**(홈 요약)로 두고 렌더러가 한 번 묻는다. 인박스의
  `inboxCounts`·`INBOX_RULES`(`shared/inbox.ts`)와 이슈 패널의 방치 판정(`issueGroups.ts`의 `STALE_MS` = 14일)을 **같이 쓴다** —
  따로 적으면 홈이 세는 수와 인박스·이슈 패널의 수가 갈린다.
- 화면: 사이드바(진입점 `홈` + 배지), 새 화면 `HomePanel`, 제목 줄 범위 `홈`(ux-polish FR-6), 앱을 열 때의 첫 화면.

## 제약

- **MCP에는 넘기지 않는다**(전체 설계 §8 — agent는 토큰의 workspace만 본다). 홈 요약은 IPC에만 열린다 — period-report와 같은 규칙.
- 세 경계(`core/`는 electron 없음 · renderer는 core 없음 · IPC는 얇다)를 지킨다.
- **App이 자식에게 내리는 prop은 필수**이고 변이로 검증한다(CLAUDE.md 컨벤션). `HomePanel`이 받는 "줄의 행동" 콜백(대화 열기 ·
  훑기로 가기 · workspace 열기)은 전부 App 배선이다.
- **"오래 안 본"의 기준은 이슈 패널과 같은 14일**(`STALE_MS`)이다 — 시안은 7일로 그렸지만 두 화면이 다른 수를 말하면 안 된다.
- 홈은 **읽기**다 — 상태를 바꾸는 버튼은 전부 기존 동작(답하기·다시 보내기·훑기)으로 보낸다. 홈에서 이슈 상태를 바꾸는 길을 만들지
  않는다(대화 쪽에서 이슈 상태를 쓰지 않는 규칙과 같은 결).
- 새 색은 `index.css` 토큰이다. 타임라인 막대의 색은 `.status-<enum>`과 같은 토큰이어야 한다.
- 짧은 새 이름(`홈`·`보기`·`답하기`)은 기존 e2e와 부분 일치로 부딪히는지 본다 — `답하기`는 대화록에 이미 있다(turn마다 하나).

## 범위 밖

- 홈에서 이슈·메모를 **편집**하는 것. 홈은 할 일 목록이지 상세가 아니다.
- 타임라인을 끌어 기간을 바꾸는 것 — 그것은 리포트다.
- 알림(OS 토스트·트레이). 홈은 앱을 열었을 때의 화면이다.
- 다른 컨셉(A·B·C·D). 특히 D(집중 피드)는 홈과 닮았지만 **workspace 화면을 대체**하는 안이라 들이지 않는다.

## 미해결 질문

- **앱을 열면 어디로 가나.** (가정: **늘 홈** — 돌고 있는 대화는 홈의 맨 위 카드라 놓치지 않는다. 대안: 돌고 있는 대화가 있으면 그
  workspace로, 마지막 화면으로.)
- **"마지막으로 대화를 보낸 workspace · repo"를 어디에 두나.** 지금 저장하는 자리가 없다. (가정: `app_setting`의 키 하나 —
  `home.lastTarget` — 마이그레이션 없음. 대안: 이 장비의 localStorage. 다른 장비로 DB를 옮기면 그 값은 따라가야 하므로 DB 쪽.)
- **홈 배지가 세는 것.** 답변 필요 + 실패·중단 + 정리 안 된 이슈 + 오래 안 본 이슈. (가정: 넷 다. 인박스 배지의 `INBOX_RULES.badge`
  칸을 그대로 쓰고 이슈 둘을 더한다 — 표를 한 곳에 두어야 한다.)
- **오늘 타임라인의 "오늘"은 자정 기준인가.** (가정: 이 장비의 로컬 자정 — 리포트의 하루 판정과 같은 함수.)
- **준비 단계의 "끝났다" 판정에 OpenCode를 넣나.** (가정: **어느 하나**가 실행 파일·인증·모델까지 초록이면 끝. OpenCode만 쓰는
  사람도 막히지 않는다.)
- **준비 단계를 다시 보는 길.** 넷이 끝난 뒤에도 설정 → 정보 탭에서 열 수 있게 할지. (가정: 두지 않는다 — 각 단계가 가는 곳이
  이미 설정 화면이다.)

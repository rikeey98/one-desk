# Spec: 사라진 asset — 안 쓴 것은 지우고, 쓴 것은 숨긴다

- 출처: 사용자 보고(2026-09-28) — "스킬·에이전트 이름을 바꾸니 예전 스킬이 그대로 있고 새 스킬이 생긴다".
  결함처럼 보이지만 설계 결정의 결과라 intent는 두지 않고 이 spec이 결정을 적는다.
- 바꾸는 설계: `docs/superpowers/specs/2026-09-07-asset-scan-design.md` §3-4("사라진 행을 지우지 않는다"),
  전체 설계 §232
- 작성자: 권용현 (초안: Claude)
- 상태: 구현 완료 (2026-09-28, 사용자가 "안 쓴 건 지우고 쓴 건 숨기기"를 골랐다)

## 1. 재현과 원인

빌드된 앱에서 재현했다(임시 e2e):

- **앱에서 만든(authored) asset의 이름 바꾸기는 정상이다** — `알파` → `알파베타`, 행 하나. 원인이 아니다.
- **repo의 skill 폴더 이름을 바꾸면(`old-skill` → `new-skill`) 옛 행이 `없음`을 달고 남고 새 행이 생긴다.**
  discovered asset의 신원은 파일 경로(`(workspace_id, file_path)`)라 폴더가 바뀌면 별개 asset이고, 사라진 행은
  "그 asset을 담았던 과거 run의 기록이 끊기지 않게" 지우지 않는다(§3-4). agent에게 skill을 만들게 하고 이름을
  바꾸게 하면 이렇게 된다.

## 2. 결정

- **FR-1.** 스캔이 끝나면, 이번에 안 보였고(`last_seen_at` < 이번 스캔 시각) **어떤 run에도 담긴 적 없는**
  (`run_context_item`에 `item_type='asset'`·그 id가 없는) discovered 행을 지운다. 끊을 기록이 없으므로 §232의
  이유가 적용되지 않는다.
- **FR-2.** 담긴 적 있는 사라진 행은 지우지 않는다(§232 그대로). 대신 **목록에서 빼고** 맨 아래 접힌
  `사라진 파일 N` 토글 안에서만 `없음`으로 보인다. 패널 머리의 개수와 절 개수는 보이는 것만 센다.
- **FR-3.** 정리 범위는 훑은 것과 같다 — repo 하나를 훑으면 그 repo의 행만, 전체 스캔이면 repo마다 + 글로벌.
- **FR-4.** **repo 루트 폴더가 없으면 그 repo는 정리하지 않는다** — 드라이브를 뺐거나 잠시 옮긴 것일 수 있다.
  글로벌 루트는 없어도 정리한다(쓰지 않는 CLI의 경로라 없는 것이 흔하고, 거기서 온 행은 이미 사라진 파일이다).
- **FR-5.** authored는 대상이 아니다.

## 3. 우려

1. 담기 칩에 올려 둔 채 파일이 사라져 정리되면 그 칩으로 실행할 때 `이 workspace에서 찾을 수 없는 asset`으로
   거부된다 — 지운 이슈를 담은 칩과 같은 동작이다.
2. 담긴 기록이 있는 행은 여전히 쌓일 수 있다(토글 안에). 그것까지 지우는 것은 §232를 버리는 결정이라 하지 않았다.

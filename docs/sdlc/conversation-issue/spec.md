# Spec: 대화에 이슈를 할당한다

- 출처: `intent.md` (승인됨 2026-10-02)
- 작성자: 권용현
- 상태: 승인됨 (2026-10-02) — plan을 쓰기 전에 개발 버전으로 먼저 써 본다(사용자: "직접 사용해 봐야 알겠다").
  써 본 뒤 바뀌는 것을 이 문서에 반영하고 plan을 쓴다.
- 작성일: 2026-10-02

## 0. intent의 미해결 질문에 대한 답

| 질문 | 이 spec의 답 | 자리 |
|---|---|---|
| 할당이 맥락 담기를 겸하는가 | **겸한다.** 할당된 이슈가 그 대화에 아직 실린 적이 없으면 다음 턴에 실린다 | FR-9~12 |
| 제목 사다리에서의 자리 | 사용자가 붙인 이름 **다음**, 담긴 이슈·메모 **앞** | FR-22 |
| 기존 대화 백필 | **하지 않는다** | FR-4 |
| 이슈를 지웠을 때 | run 테이블에 쓰지 않는다. **읽을 때 걸러** 공통 대화로 보이고, 그 대화를 곧바로 다시 알린다 | FR-3·26 |
| 이슈에서 시작할 때 작업 디렉토리 | **지금 규칙 그대로**(사이드바에서 고른 repo) | FR-16 |
| `대화 N`의 모양 | 여는 단추 하나 + 목록 단추 `▾` 하나로 다듬었다 | FR-13·14 |
| 패널 창 | 대화 단추를 **그리지 않는다** | FR-18 |
| "다시 실행" | 할당을 **따라가지 않는다** | §1 빠지는 것 |
| 인박스 "관련 이슈 닫기" | **그대로 둔다** | §1 빠지는 것, §6 우려 4 |
| MCP | `list_conversations`·`get_conversation`에 `issueId`를 싣는다 | FR-25 |
| (spec 검토에서 나온 것) 이슈를 담아 시작한 대화 | **첫 턴에 이슈가 하나뿐이면 자동으로 할당한다**(2026-10-02 결정) | FR-27 |
| (spec 검토에서 나온 것) 이슈 상세에서 연 대화의 확인 | **도크 목록에서 누른 것과 같이 확인된다**(2026-10-02 결정) | FR-17 |

## 1. 범위

여섯 조각이다. (A)·(B)가 core의 저장과 쓰기, (C)가 할당이 실제 프롬프트에 닿는 규칙, (D)·(E)가 두
방향의 화면, (F)가 MCP다.

- **(A) 대화(뿌리)에 이슈 칸 하나.** 마이그레이션 `0010`, **컬럼 추가만.**
- **(B) 할당·해제.** 새 대화를 이슈와 함께 시작하거나, 이미 있는 대화에 붙이고 뗀다.
- **(C) 할당은 맥락을 겸한다.** 아직 실린 적 없는 할당 이슈는 다음 턴에 실린다.
- **(D) 이슈 → 대화.** 이슈 상세의 대화 단추.
- **(E) 대화 → 이슈.** 대화 헤더의 이슈 링크, 메뉴의 할당·해제, 제목 사다리.
- **(F) MCP와 반영.** 대화 요약에 할당된 이슈 id. 이슈를 지우거나 이름을 바꾸면 그 대화가 곧바로 따라간다.

**빠지는 것**

- **이슈의 상태를 대화 쪽에서 쓰는 모든 것** — 헤더에서 바꾸기, 대화를 시작할 때 "진행 중", 끝낼 때
  "완료". 상세 밖의 쓰기는 열린 상세에 충돌 배너를 띄운다(본문 설계 §137, intent 제약).
- **이슈 본문이 바뀌었다는 `수정됨` 표시**(intent의 "뺀 것").
- **"다시 실행"이 할당을 따라가는 것.** 인박스 항목은 대표 턴이라 뿌리의 할당을 들고 있지 않고, 인박스는
  workspace를 가로질러 App의 run 목록 밖에 있다. 새 대화는 공통으로 시작하고, 필요하면 할당한다.
- **인박스의 "관련 이슈 닫기"를 할당 기준으로 바꾸는 것**(§6 우려 4).
- **도크 목록 줄의 표시.** 할당된 대화의 제목이 이미 이슈 이름이다(FR-22).
- **MCP로 할당하는 도구.** agent가 대화의 주제를 바꿀 이유가 아직 없다.

## 2. 기능 요구사항

### (A) 데이터

- **FR-1.** `run` 테이블에 `issue_id text`를 더한다. **뿌리 행에서만 의미가 있다** — 이어지는 턴의 행에서는
  늘 null이다. **외래키를 걸지 않는다**: `run_context_item.item_id`와 같은 판단이다(`schema.ts:170` — 이슈를
  지워도 대화 기록에 손대지 않는다). 선례는 `root_run_id`다(`drizzle/0002`, `ALTER TABLE ADD COLUMN` 한 줄).
- **FR-2.** `Run`에는 날것의 `issueId`가 아니라 **`issue: { id, title } | null`**로 싣는다. 이름은 core가
  읽는 시점에 붙인다(`loadContext`의 `livingNames`와 같은 자리, 같은 한 번의 `inArray`). **날것의 컬럼이
  `Run`에 새지 않는다** — `hydrate`의 스프레드가 흘려보내므로 사용량 컬럼처럼 떼어 낸다(CLAUDE.md의
  "`Run`을 만드는 스프레드" 함정). 둘 다 실리면 `issueId`는 죽은 id를, `issue`는 null을 말하는 날이 온다.
- **FR-3.** **지워진 이슈는 읽을 때 null이다.** `issue_id`에 죽은 id가 남아도 `Run.issue`는 null이고, 그
  대화는 공통 대화로 보인다. 이슈 저장소의 삭제는 바뀌지 않는다 — 다른 테이블을 쓰지 않는다.
- **FR-4.** 마이그레이션 `0010`은 `ALTER TABLE run ADD issue_id text`와 그 칸의 인덱스뿐이다(FR-26이 이슈
  id로 대화를 찾는다). **백필이 없다** — 기존 대화는 전부 공통 대화다. **테이블을 다시 만들지 않는다**:
  `DROP TABLE run`이 `run_context_item`의 cascade를 태운다. drizzle이 만든 SQL을 반드시 읽는다.

### (B) 할당·해제

- **FR-5.** `StartRunInput`에 `issueId?: string | null`이 생긴다. 주면 그 이슈가 할당된 **새 대화**가 된다.
  `parentRunId`와 함께 오면 던진다 — 할당은 뿌리에만 찍히는데 `parentRunId`가 있는 run은 뿌리가 아니다.
- **FR-6.** `runs.assignIssue(rootRunId, issueId | null)`이 이미 있는 대화의 할당을 바꾼다. null이면 뗀다.
  - 뿌리가 아닌 id면 던진다(`assertRoot` — `close`·`rename`과 같은 방어선).
  - 이슈가 없거나 **대화와 다른 workspace**면 던진다. 외래키는 존재만 보고 소속은 보지 않는다(CLAUDE.md
    데이터 규칙).
  - **같은 workspace의 이슈면 된다** — repo로 거르지 않는다(intent 제약 "규칙을 늘리지 않는다").
  - 끝낸 대화에도 할당할 수 있다. 할당은 대화를 되살리지 않는다(되살리는 것은 새 턴뿐이다, lifecycle FR-13).
- **FR-7.** `assignIssue`는 `close`·`rename`과 같이 core의 `conversations` 래퍼에서 `RUN_UPDATE`와
  `emitInbox()`를 짝으로 낸다. 렌더러는 기존 `onRunUpdate` 구독으로 뿌리 행을 갈아 끼운다 — 새 이벤트가 없다.
- **FR-8.** 같은 이슈를 할당하는 대화의 수에는 제한이 없다. **이슈 하나에 대화가 여럿일 수 있다**(intent 결정).
- **FR-27.** **새 대화의 첫 턴에 담은 이슈가 정확히 하나면 그 이슈를 할당한다**(2026-10-02 결정). 지금처럼 이슈를
  담아 도크에서 보내는 습관이 그대로 이어진다 — 제목은 이슈 이름인데 이슈 상세는 그 대화를 모르는 상태가 생기지
  않는다.
  - 할당 예정(FR-20)이 있으면 그것이 이긴다. 이슈를 둘 이상 담았거나 하나도 없으면 할당하지 않는다.
  - 이어 가는 턴에는 적용하지 않는다 — 새 대화(뿌리)를 만들 때뿐이다.
  - 판정은 core의 `start` 한 자리다. 틀렸으면 `⋯`에서 뗀다(FR-21).

### (C) 할당은 맥락을 겸한다

- **FR-9.** 규칙은 하나다: **할당된 이슈가 그 대화의 어느 턴 맥락에도 없으면, 다음 턴의 맥락에 더한다.**
  취소된 턴은 세지 않는다(`collectContext`가 "담으려다 만 것"으로 빼는 것과 같다). 실린 적이 있으면 다시
  싣지 않는다 — 할당을 뗐다 다시 붙여도 마찬가지다.
- **FR-10.** 규칙은 **`shared/`의 순수 함수 하나**다. core는 턴을 실행할 때 그것으로 맥락을 더하고, 렌더러는
  입력부에 같은 것을 보인다(FR-12). 따로 적으면 화면은 "실립니다"라는데 실리지 않는 날이 온다
  (`INBOX_RULES`를 `shared/`에 둔 것과 같은 이유).
- **FR-11.** core가 더한다 — `start`(FR-5의 이슈)와 `resume`(이어 가는 턴) 둘 다. 사용자가 같은 이슈를 칩으로도
  담았으면 **한 번만** 싣는다(`run_context_item`에 같은 항목이 두 줄 생기면 안 된다). 더하는 것은 행을 만들기
  전이다 — 소속 검증(`collectContext`의 `assertFound`)을 그대로 탄다.
- **FR-12.** 입력부의 칩 줄에 **읽기 전용 칩** `할당된 이슈 · <제목>`이 선다 — FR-9가 다음 턴에 실을 때만.
  빼기 단추가 없다(빼려면 할당을 뗀다, FR-21). 칩 줄은 "이번 턴에 담을 것"이고 이것도 그중 하나다. 담은
  것이 없어 칩 줄이 없던 입력부에도 이 칩 하나로 줄이 선다.

### (D) 이슈 → 대화

- **FR-13.** 이슈 상세의 메타 줄(`.detail-meta`, repo 태그 다음·시각 앞)에 **여는 단추** 하나가 선다.
  - 끝내지 않은 대화가 있으면 `대화 열기` — 가장 최근 것(도크 목록과 같은 정렬)을 연다. 상태 점이 붙고 점은
    도크 목록 줄과 같은 규칙(`conv.active ?? conv.state`, `RUN_STATUS_LABELS`)이다.
  - 없으면 `대화 시작`(FR-15).
  - **끝낸 대화는 여는 단추가 보지 않는다.** 인수인계("대화 끝내기 → 이슈에서 다시 시작", intent 원하는
    결과)가 그대로 되려면, 끝낸 대화만 남은 이슈의 단추는 `대화 시작`이어야 한다.
- **FR-14.** 그 이슈의 대화가 하나라도 있으면 곁에 **목록 단추** `▾`가 선다(개수 알약 `.group-count`).
  누르면 메뉴가 뜬다.
  - 그 이슈의 대화 전부 — 끝내지 않은 것이 먼저(최근순), 끝낸 것이 뒤. 줄마다 상태 점 · 턴 수 · 마지막 시각,
    끝낸 대화면 `끝낸 대화`, 이름을 따로 붙인 대화면 그 이름.
  - 맨 아래 `이 이슈로 새 대화` — 끝내지 않은 대화가 있어도 하나 더 시작한다(agent 바꾸기·다시 시도).
  - 메뉴는 대화 헤더의 `⋯` 메뉴와 같은 모양이다 — popover, ↑↓, Esc가 안쪽부터 푼다(timeline FR-35·39).
- **FR-15.** `대화 시작`(과 `이 이슈로 새 대화`)은 **도크를 펼치고 새 대화 칸으로 옮긴다.** 그 칸에는 그 이슈가
  **할당 예정**으로 걸린다(FR-20). 보내면 FR-5로 시작한다. 입력칸의 초안·담기 칩은 건드리지 않는다.
- **FR-16.** 새 대화의 작업 디렉토리는 **지금 규칙 그대로**다(v0.19.2 — 사이드바에서 고른 repo, 없으면 첫 repo,
  입력부의 알약으로 바꾼다). 이슈의 repo 태그로 정하지 않는다(intent 제약).
- **FR-17.** `대화 열기`와 메뉴의 대화 줄은 도크에서 그 대화를 연다 — 인박스의 "대화 열기"와 같은 길
  (`focusConversationId`)이다. **그리고 도크 목록에서 누른 것처럼 확인된다**(2026-10-02 결정) — 사용자가 그 대화를
  골라 누른 것이라 lifecycle FR-6이 막으려던 "보지도 않은 대화가 저절로 확인되는 것"이 아니다. 판정은 도크 목록과
  **같은 함수**다(`INBOX_RULES`의 `clearsOnView` — 답변 필요는 열어도 남는다). 확인은 이 클릭에서 부르고,
  `focusConversationId` 길 자체에는 걸지 않는다 — 인박스의 "대화 열기"는 그대로다.
- **FR-18.** **패널 창의 이슈 상세에는 두 단추가 없다.** 창에는 도크가 없다. 패널의 `context` prop처럼 선택
  prop이고 App만 넘긴다(item-windows FR-8과 같은 구조).
- **FR-19.** 단추가 보는 "이 이슈의 대화"는 **App이 이미 가진 run 목록**(`useRuns`)에서 묶는다 — 새 조회가 없다.
  run이 끝나거나 할당이 바뀌면 `onRunUpdate`로 함께 바뀐다.

### (E) 대화 → 이슈

- **FR-20.** **새 대화 칸에 할당 예정이 걸려 있으면** 헤더의 `새 대화` 아래에 `이슈 · <제목>`이 서고,
  곁에 `이슈 할당 해제`가 있다. 예정은 첫 턴을 보내면 할당이 되고(FR-5), 해제하거나 workspace를 바꾸면
  사라진다. 도크에서 다른 대화를 보다 새 대화 칸으로 돌아와도 남아 있다 — 담기 칩과 같은 수명이다.
- **FR-21.** **할당된 대화의 헤더**에는 부제 곁에 이슈 링크가 선다. 누르면 그 이슈 상세가 열린다(App의
  `openIn('issue', id)` — 패널이 넓어진다). `⋯` 메뉴에 항목이 더해진다.
  - 할당이 없으면 `이슈 할당`, 있으면 `이슈 바꾸기`와 `이슈 할당 해제`.
  - `이슈 할당`·`이슈 바꾸기`는 **이슈 고르기**를 연다: 그 workspace의 이슈, 완료가 아닌 것이 먼저(최근에
    만든 순), 완료가 뒤. 위의 입력칸이 제목으로 거른다. 지금 할당된 것은 표시된다. 목록은 열 때 한 번 읽는다.
  - 해제·바꾸기에 확인 단계가 없다 — 지우는 것이 없고 되돌리기가 한 번이다.
- **FR-22.** 제목 사다리에 한 칸이 들어간다(lifecycle FR-11의 개정).
  1. 사용자가 붙인 이름
  2. **할당된 이슈의 제목** ← 새 칸. `+N`을 붙이지 않는다 — 할당은 하나다.
  3. 담긴 이슈·메모의 첫 이름(`+N`)
  4. 첫 repo 이름
  5. 첫 지시의 첫 줄
- **FR-23.** 링크의 이름은 **이슈 제목만으로 된 이름이 아니다.** 이슈 목록 줄을 `{ name: <제목>, exact: true }`로
  잡는 e2e와 부딪힌다 — 대화 제목이 버튼이 아닌 것과 같은 이유다(timeline FR-34). §5 NFR-5의 이름을 쓴다.
- **FR-24.** "이 대화에 담긴 것" 줄은 그대로다. 할당된 이슈도 실린 뒤에는 거기에 다른 항목과 같이 보인다.

### (F) MCP와 반영

- **FR-25.** `list_conversations`의 줄과 `get_conversation`의 결과에 **`issueId: string | null`**을 싣는다
  (지워진 이슈는 null — FR-3). 도구 설명에 "이 대화에 할당된 이슈. 본문은 get_issue로"를 더한다. 기간 정리
  (`docs/ideas.md`)가 대화와 이슈를 묶어 말할 수 있게 된다. 읽기 전용 권한에서도 그대로 보인다.
- **FR-26.** **이슈를 지우거나 제목을 바꾸면, 그 이슈가 할당된 대화의 뿌리를 다시 알린다**(`RUN_UPDATE`). run
  테이블에는 쓰지 않는다 — 다시 읽어 알릴 뿐이고, 다시 읽으면 FR-3 덕에 지운 이슈는 null, 바꾼 제목은 새
  이름이다. 이것이 없으면 지운 이슈의 링크가 다음 run 갱신까지 헤더에 남아, 누르면 없는 이슈를 연다.
  - 자리는 이슈 저장소를 감싸 바뀜 알림을 내는 곳(`core/changes.ts`의 래퍼와 같은 자리)이다 — IPC와 MCP가 같은
    감싼 저장소를 받는다.
  - 제목이 든 쓰기에만 돈다. 본문 자동 저장(600ms 디바운스)마다 돌면 쓸데없이 run을 다시 읽는다.
  - 받는 쪽이 부담이 없다: 이슈 목록은 이미 이슈가 바뀔 때마다 다시 읽고(`useIssues`의 `useItemChanged`),
    run 갱신으로는 run마다 한 번만 다시 읽는다.

```
새 대화

─────────────────────────────── (대화록 비어 있음)

[지시를 입력…                                ]
```

  아이콘은 `aria-hidden`이고 이름은 `aria-label`이 준다.

- 링크 모양(`이슈 ↗`)과 정확한 배치는 plan에서 실제 앱 캡처(라이트·다크)로 고른다.

## 5. 비기능 요구사항

- **NFR-1.** `assignIssue`는 한 번의 UPDATE다. `start`의 행 생성은 지금처럼 한 트랜잭션이다(`create`).
- **NFR-2.** `Run.issue`의 이름은 `hydrate` 한 번에 `inArray` 한 번으로 붙인다 — run마다 조회하지 않는다(N+1).
- **NFR-3.** 경계 셋 그대로 — `core/`는 electron 모름, `renderer/`는 core 모름, IPC 얇음.
- **NFR-4.** 대비 4.5:1. 안내문을 `opacity`로 흐리지 않고 `--text-muted`를 쓴다.
- **NFR-5.** 새 이름은 기존 이름과 **부분 일치로도** 부딪히지 않게 고른다. 안:
  - 이슈 상세: `이 이슈로 대화 시작` · `이 이슈의 대화 열기` · `이 이슈의 대화 목록` · (메뉴 항목) `이 이슈로 새 대화`
  - 대화 헤더: `할당된 이슈 열기` · (메뉴 항목) `이슈 할당` · `이슈 바꾸기` · `이슈 할당 해제`
  - 새 대화 칸: `이슈 할당 해제`(헤더 메뉴의 것과 같은 이름 — 한 화면에 둘이 함께 서지 않는다)
  - 이슈 고르기: 입력칸 `할당할 이슈 찾기`, 목록 `할당할 이슈`
  인박스의 `대화 열기`는 `이 이슈의 대화 열기`의 부분 문자열이다 — 인박스와 이슈 상세는 한 화면에 함께 서지
  않지만, 새 e2e는 `exact`로 잡는다. 상태 점의 상태 이름은 단추 **이름에 넣지 않는다**(도크 목록 줄처럼 이름이
  상태마다 바뀌면 e2e가 상태마다 깨진다) — `title`로 보인다.
- **NFR-6.** UI 변경은 실제 앱 캡처(라이트·다크)로 확인한다.

## 6. 우려 사항 (Areas of concern)

1. **할당이 아니라 담기만 한 대화의 이름은 여전히 늦게 바뀐다.** FR-26은 할당된 대화의 뿌리만 다시 알린다. 이슈를
   맥락으로 담기만 한 대화(그 이슈 이름이 제목인 대화 포함)는 지금처럼 다음 run 갱신까지 옛 이름이다 — 지금의 맥락
   이름(`contextItems[].label`)과 같은 성질이고, 이 기능이 만든 틈이 아니다. 전부 풀려면 렌더러가 이슈 바뀜
   알림마다 run 목록(`assembled_prompt` 포함)을 다시 읽어야 해 두었다.
2. **예약이 걸린 중에 할당하면 한 턴 늦게 실린다.** 예약된 턴은 이미 프롬프트가 조립됐다. 할당은 그다음 턴에
   실리고, 예약이 있는 동안 전송이 잠겨 있어 FR-12의 칩도 그때 보인다. 드문 경우라 두었다.
3. **자동 할당(FR-27)은 참고로 담은 이슈 하나도 할당한다.** 새 대화 첫 턴에 이슈 하나만 담았다면 거의 그것이
   주제라 받아들였다(2026-10-02 결정). 틀렸으면 `⋯`에서 뗀다.
4. **인박스의 "관련 이슈 닫기"는 그대로 대표 턴의 맥락을 본다.** 할당 이슈는 첫 턴에만 실리므로, 대화가 이어진 뒤의
   인박스 항목에는 그 단추가 뜨지 않는다. **지금도 같다**(첫 턴에 담은 이슈) — 이 기능이 만든 틈은 아니지만 더 눈에
   띈다. 인박스 항목에 뿌리의 할당을 실으려면 `inbox()`가 뿌리를 따로 읽어야 해 별도로 다룬다.
5. **메타 줄이 붐빈다.** 상태 · 축 셋 · repo 태그 · 대화 단추 둘 · 시각과 id. 넘치면 줄바꿈이라 깨지지는 않지만
   본문이 내려간다. 1280px·1440px 캡처로 확인하고, 많이 내려가면 단추를 아이콘으로 줄인다.
6. **이슈 상세에서 연 대화는 확인되고, 인박스에서 연 대화는 확인되지 않는다**(FR-17). 둘 다 사용자가 누른 것인데
   규칙이 갈린다. 인박스는 "확인함" 단추가 따로 있는 화면이라 그대로 두었다 — 써 보고 어색하면 맞춘다.
7. **끝내지 않은 대화가 둘 이상이면 `대화 열기`는 가장 최근 것만 연다.** 나머지는 `▾` 메뉴로 간다. 평소 한 이슈에 열린
   대화는 하나라 두었다.
8. **`issue_id`에 외래키가 없다.** 이슈를 지우면 죽은 id가 남고, 읽을 때마다 거른다(FR-3). 같은 이슈 id가 다시 생길
   일은 없다(UUID). 행을 실제로 비우는 쪽이 깔끔하지만 이슈 저장소가 run 테이블을 쓰게 된다 — 맥락 기록과 같은
   쪽을 골랐다.

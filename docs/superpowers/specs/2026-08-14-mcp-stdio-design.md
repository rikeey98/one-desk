# MCP를 stdio 전송으로 옮기는 설계

**날짜:** 2026-08-14
**상태:** 승인됨
**근거:** 실측 — 대상 Windows 환경에서 루프백 HTTP가 사내 프록시에 막힘

---

## 1. 왜 옮기는가

대상 환경에서 agent가 MCP 서버에 붙지 못한다. 실측으로 좁힌 결과:

| 관측 | 뜻 |
|---|---|
| 사이드바에 `MCP :11397` | 서버는 떠 있다 |
| `curl http://127.0.0.1:11397/mcp` → **401** | 포트는 그 장비에서 도달 가능하다 |
| agent만 실패, `code: 403` | **우리 서버가 낼 수 없는 코드다** — 404·401·400·200·202뿐 |
| `HTTP_PROXY`가 설정돼 있음 | 사내 프록시가 루프백 중계를 거부하고 403을 돌려준다 |

`NO_PROXY`에 루프백을 더하는 완화(v0.1.3)를 넣었지만, **이 환경은 루프백 HTTP 자체가 정책으로 막혀 있다.** 프록시를 우회해도 엔드포인트 보안이 같은 자리를 막을 수 있고, 어느 쪽도 우리가 통제할 수 없다.

**stdio 전송은 네트워크를 쓰지 않는다.** 클라이언트가 서버를 자식 프로세스로 띄우고 stdin/stdout으로 JSON-RPC를 주고받는다. 프록시·방화벽·포트·TLS 검사가 관여할 여지가 원천적으로 없다.

---

## 2. 구조 — 브리지 하나만 더한다

**MCP 서버 자체는 그대로 둔다.** 도구 아홉 개, 토큰별 권한 게이팅, 요청마다 새 인스턴스 — 4단계에서 검증한 것을 다시 쓰지 않는다.

```
claude ──stdio(JSON-RPC 줄)──> bridge.mjs ──HTTP──> 앱 안의 MCP 서버
                                (우리 프로세스)      (127.0.0.1, 상시 기동)
```

**브리지의 HTTP 호출은 프록시를 타지 않는다.** Node의 `http`/`fetch`는 `HTTP_PROXY`를 자동으로 쓰지 않는다 — 명시적으로 프록시 에이전트를 붙여야만 탄다. 우리는 붙이지 않는다. 그래서 같은 루프백 주소인데도 claude가 실패하는 자리를 브리지는 통과한다.

**브리지는 멍청한 파이프다.** JSON-RPC를 해석하지 않는다.

```
stdin 한 줄 → POST /mcp (Authorization: Bearer …) → SSE의 data: 줄 → stdout 한 줄
```

id가 없는 알림은 서버가 202와 빈 본문을 주므로 아무것도 쓰지 않는다.

### 왜 브리지가 DB를 직접 열지 않는가

열면 도구 아홉 개와 권한 게이팅을 브리지에 복제해야 하고, better-sqlite3를 자식 프로세스에 실어야 하며, 쓰기 잠금이 앱과 경쟁한다. **파이프 하나가 훨씬 싸다.**

---

## 3. 설정 파일이 바뀐다

```json
{
  "mcpServers": {
    "one-desk": {
      "command": "<execPath>",
      "args": ["<bridgePath>"],
      "env": {
        "ELECTRON_RUN_AS_NODE": "1",
        "ONE_DESK_MCP_URL": "http://127.0.0.1:<port>/mcp",
        "ONE_DESK_MCP_TOKEN": "<token>"
      }
    }
  }
}
```

**`command`는 Electron 바이너리다.** 패키징된 앱에는 독립 `node`가 없다. `ELECTRON_RUN_AS_NODE=1`을 주면 Electron이 순수 Node로 동작한다.

**토큰은 여전히 인자에 넣지 않는다.** 0600 설정 파일 안의 `env`에 담기고, claude가 그것을 브리지의 환경으로 넘긴다. 프로세스 환경은 같은 사용자에게만 보이므로 파일과 같은 수준이다.

**`core/`는 `electron`을 import하지 않는다.** `execPath`와 `bridgePath`를 `createMcpHost` 옵션으로 받는다 — 마이그레이션 디렉토리를 받는 것과 같은 방식이다.

---

## 4. 브리지 파일의 위치

`drizzle`과 똑같이 다룬다.

| | 경로 |
|---|---|
| 개발 | `<appPath>/core/mcp/bridge.mjs` |
| 패키징 | `<resourcesPath>/mcp-bridge.mjs` (`extraResources`) |

**asar 안에 두지 않는다.** `ELECTRON_RUN_AS_NODE`로 띄운 프로세스가 asar 내부 경로를 실행할 수 있는지가 플랫폼마다 미묘하다 — 그 불확실성을 살 이유가 없다. 번들되지 않는 `.mjs` 원본을 그대로 복사한다(`fake-claude.mjs` 픽스처와 같은 성질이다).

---

## 5. 그대로 남는 것

- **HTTP 서버와 상시 기동, 사이드바 상태 표시.** 브리지가 그 서버에 붙는다. 상태 줄은 여전히 "서버가 떴는가"를 보여준다.
- **토큰 발급과 폐기.** run 단위 그대로다.
- **`--mcp-config` · `--strict-mcp-config` · `--allowedTools`.** 어댑터는 바뀌지 않는다.
- **`withLoopbackBypass`.** stdio가 프록시를 안 타므로 이제 불필요해 보이지만 **남긴다** — 브리지의 HTTP 호출이 어떤 이유로든 프록시를 타게 되는 미래를 막는 보험이고, 원격 호출에는 영향이 없다.

---

## 6. 검증

| 항목 | 방법 |
|---|---|
| 브리지가 요청을 왕복시킨다 | 단위 — 브리지를 spawn해 `tools/list`를 넣고 응답을 받는다 |
| 알림은 응답을 쓰지 않는다 | 단위 — id 없는 메시지에 stdout이 조용하다 |
| 서버가 죽어 있으면 JSON-RPC 오류를 돌려준다 | 단위 — 매달리지 않는다 |
| 설정 파일이 stdio 형태다 | 단위 — `command`/`args`/`env` 키 |
| **진짜 claude가 붙고 도구 아홉 개가 보인다** | **`ONE_DESK_REAL_CLI=1`** — 이 계약이 이번 변경의 전부다 |
| 앱 한 바퀴 | e2e — 가짜 CLI가 브리지를 실제로 띄운다 |

**마지막 두 줄이 이 작업의 완료 조건이다.** HTTP 형식이 진짜 CLI로 검증된 적 없었던 탓에 이 사달이 났다 — 같은 실수를 되풀이하지 않는다.

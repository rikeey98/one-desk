## 이번 버전에서 바뀐 것 (v0.25.0 → v0.25.1)

데이터베이스 마이그레이션은 없습니다.

### 고친 것

- **WSL repo의 대화와 터미널이 실제로 돕니다.** v0.24.0·v0.25.0에서는 `claude 실행 환경`을 `WSL`로 바꾼 repo에서 대화를 시작하면
  `MCP 서버를 준비하지 못했습니다: WSL 경로를 변환하지 못했습니다 …`로 시작조차 못 했고, 터미널 칸도 뜨지 않았습니다. one-desk가
  `wsl.exe`에 넘기는 인자를 WSL의 셸이 다시 해석하면서 Windows 경로의 `\`가 사라졌기 때문입니다. 이제 셸을 거치지 않고 인자를
  그대로 넘깁니다.
  - 실제 WSL(Ubuntu 24.04)에서 확인한 것: WSL 안의 claude로 대화 · MCP 도구 호출(이슈 목록 읽기) · `@` 파일 멘션 · 코드 칸 ·
    WSL 터미널 · 큰 셸 출력 · 취소(WSL 안의 자식 프로세스까지 정리) · 앱을 끈 뒤 WSL과 Windows에 남는 프로세스 없음.
- **Windows 사용자 이름에 한글 같은 글자가 있으면 WSL 대화에서 agent가 이슈·메모 도구를 못 쓰던 것을 고쳤습니다.** MCP 연결을
  띄우는 배치 파일이 그 경로를 깨뜨렸습니다.
- **repo 탭에서 실행 환경이나 경로를 바꿔 저장하면 실행 탭의 CLI 상태를 곧바로 다시 확인합니다.** 전에는 WSL로 바꾼 직후의
  `Claude Code (WSL · <배포판>)` 줄이 1분 넘게 "확인 중"으로 남았습니다.

### 알아 둘 것

- v0.24.0의 WSL 안내는 그대로입니다 — WSL의 환경변수는 `~/.profile`(또는 `/etc/environment`)에, 배포판의 interop은 켜 둔 채로,
  claude 세션은 실행 환경마다 따로입니다.
- WSL 안의 claude가 로그인돼 있어야 합니다. 터미널에서 `wsl`로 들어가 `claude`를 한 번 실행해 로그인하세요.
- 아직 남은 것 셋:
  - **로그인 정보를 `~/.profile`에 둔 경우**(Bedrock 같은 환경변수): 실행 탭의 WSL 줄이 "로그인 필요"로 보일 수 있습니다. 대화는
    정상으로 돕니다.
  - **WSL 터미널에서 백그라운드로 띄운 작업**(`npm run dev &` 같은 것): 앱을 꺼도 남을 수 있습니다. 끄기 전에 직접 멈추세요.
  - **Windows 사용자 폴더 경로에 `&`·`^`·`%`가 있으면** WSL 대화에서 이슈·메모 도구가 붙지 않습니다.

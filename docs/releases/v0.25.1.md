## 이번 버전에서 바뀐 것 (v0.25.0 → v0.25.1)

데이터베이스 마이그레이션은 없습니다.

### 고친 것 — WSL repo

v0.24.0에서 들어온 WSL repo 기능을 실제 WSL(Ubuntu 24.04)에서 처음 돌려 보고 찾은 것들을 고쳤습니다.

- **WSL repo의 대화와 터미널이 실제로 돕니다.** v0.24.0·v0.25.0에서는 `claude 실행 환경`을 `WSL`로 바꾼 repo에서 대화를 시작하면
  `MCP 서버를 준비하지 못했습니다: WSL 경로를 변환하지 못했습니다 …`로 시작조차 못 했고, 터미널 칸도 뜨지 않았습니다. one-desk가
  `wsl.exe`에 넘기는 인자를 WSL의 셸이 다시 해석하면서 Windows 경로의 `\`가 사라졌기 때문입니다. 이제 셸을 거치지 않고 인자를
  그대로 넘깁니다.
- **실행 탭의 `Claude Code (WSL · <배포판>)` 줄이 대화와 같은 환경으로 판정합니다.** Bedrock 같은 환경변수를 WSL의 `~/.profile`에 둔
  경우, 이 줄이 "인증 확인 불가"나 엉뚱한 모델로 보이던 것을 고쳤습니다.
- **repo 탭에서 실행 환경이나 경로를 바꿔 저장하면 실행 탭의 CLI 상태를 곧바로 다시 확인합니다.** 전에는 WSL로 바꾼 직후의 WSL
  줄이 1분 넘게 "확인 중"으로 남았습니다.

WSL 대화와 터미널이 실제로 돌게 되면서 드러난 것도 같이 고쳤습니다.

- **Windows 사용자 폴더 이름에 한글이나 `&`·`^`·`%`·괄호가 있어도 WSL 대화에서 agent가 이슈·메모 도구를 씁니다.** 도구 연결을
  배치 파일로 띄우면 그런 이름의 경로가 깨집니다. 배치 파일 없이 직접 띄우도록 바꿨습니다.
- **WSL 터미널을 다시 시작하거나 앱을 끄면, 그 셸에서 띄운 작업까지 끝납니다.** `npm run dev &`처럼 백그라운드로 띄운 작업도,
  `nohup`·`disown`으로 띄운 것도 함께 끝납니다(Windows 셸 칸과 같습니다). `setsid`처럼 스스로 세션을 떠난 것만 남습니다.

실제 WSL에서 확인한 것: WSL 안의 claude로 대화 · 이슈 도구 호출 · `@` 파일 멘션 · 코드 칸 · WSL 터미널 · 큰 셸 출력 · 취소(WSL 안의
자식 프로세스와 Windows 쪽 도구 연결까지 정리) · 셸 다시 시작과 앱 종료 뒤 남는 프로세스 없음(도는 대화가 없을 때). 앱의 데이터 폴더
이름에 한글과 특수 문자를 섞어 돌렸습니다.

### 알아 둘 것

- v0.24.0의 WSL 안내는 그대로입니다 — WSL의 환경변수는 `~/.profile`(또는 `/etc/environment`)에, 배포판의 interop은 켜 둔 채로,
  claude 세션은 실행 환경마다 따로입니다.
- WSL 안의 claude가 로그인돼 있어야 합니다. 터미널에서 `wsl`로 들어가 `claude`를 한 번 실행해 로그인하세요. 로그인하지 않았으면
  실행 탭의 WSL 줄은 "로그인 필요"가 아니라 "인증 확인 불가 (종료 코드 1)"로 보입니다.
- WSL 터미널에서 `exit`로 셸을 먼저 끝냈다면, 그 셸에서 백그라운드로 띄운 작업은 다시 시작이나 앱 종료 때 끝나지 않습니다. 끝내려면
  셸을 끝내기 전에 멈추세요. 앱과 상관없이 계속 돌아야 하는 것은 `setsid`로 띄우세요.

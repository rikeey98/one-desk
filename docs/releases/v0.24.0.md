## 이번 버전에서 바뀐 것 (v0.23.0 → v0.24.0)

**첫 실행에 데이터베이스 마이그레이션이 돕니다** — repo에 `claude 실행 환경` 한 칸이 생깁니다(기본 Windows). 되돌릴 일은 없습니다.

### 새 기능

- **WSL2 안의 repo를 WSL 안의 claude로 돌립니다.** Windows에서 설정 › repo 탭의 `claude 실행 환경`을 `WSL`로 바꾸면 그 repo의
  모든 프로세스 — claude 실행, 슬래시 커맨드 조회, CLI 상태, 파일 목록, 터미널 셸 — 가 `wsl.exe`로 그 배포판 안에서 뜹니다.
  - repo 경로는 `\\wsl$\<배포판>\…`(탐색기의 Linux 항목에서 복사한 것)으로 등록합니다. 배포판과 Linux 경로는 그 경로에서 읽습니다.
  - WSL 안의 claude는 로그인 셸(`bash -l`)에서 `claude`를 찾습니다. 다른 곳에 있으면 설정 › 앱 탭의 `WSL claude 경로`에 Linux 경로를
    적습니다. 실행 탭의 CLI 상태에 `Claude Code (WSL · <배포판>)` 줄이 섭니다.
  - 글로벌 skill은 WSL 홈의 `~/.claude/skills`를 봅니다(앱 탭의 `WSL 글로벌 skill 경로`에서 바꿉니다).
  - 터미널 칸은 그 배포판의 셸(`$SHELL`)이고 머리에 `wsl · <배포판>`이 보입니다.
  - 이슈·메모·대화는 지금처럼 one-desk의 DB에, 코드 수정은 WSL 폴더에 됩니다. 코드 칸의 파일 읽기·쓰기는 Windows가 UNC 경로로 합니다.
  - WSL repo에서 OpenCode는 아직 고를 수 없습니다.

### 알아 둘 것

- **WSL의 환경변수는 `~/.profile`(또는 `/etc/environment`)에 두세요.** 로그인 셸이 읽는 것은 그 파일이고, Ubuntu의 `~/.bashrc`는
  비대화형이면 맨 위에서 돌아가 거기 적은 `export`가 보이지 않습니다. Bedrock 변수와 `NO_PROXY`가 여기에 해당합니다.
- **claude 세션은 환경마다 따로입니다.** Windows claude로 시작한 대화는 WSL claude로 이을 수 없습니다 — 실행 환경을 바꾸면 새 대화로
  시작하세요.
- **배포판의 interop이 켜져 있어야 합니다**(기본값). MCP 브리지는 Windows 쪽에 남고 WSL 안의 claude가 Windows 실행 파일을 띄웁니다.
  `/etc/wsl.conf`에서 `interop.enabled=false`로 끈 배포판에서는 agent가 이슈·메모를 읽고 쓰지 못합니다. 앱 설치 폴더(`C:\…`)가
  WSL 안에서 `/mnt/c/…`로 보여야 하는 것도 같은 이유입니다(automount 기본값).
- **이 기능은 실제 WSL에서 실측하지 못한 채 나갑니다.** 설계는 어느 쪽이든 되게 했지만, 안 되는 것이 있으면(MCP 도구가 안 붙는다,
  취소해도 WSL 안의 프로세스가 남는다, 큰 출력이 밀린다) 이슈로 알려 주세요 — 대화의 `자세히`와 `logs/<runId>/raw.jsonl`이 재료입니다.

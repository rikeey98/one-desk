## 이번 버전에서 바뀐 것 (v0.26.0 → v0.26.2)

데이터베이스 마이그레이션은 없습니다. Linux 판(AppImage)만 고쳤습니다 — Windows 판은 동작이 그대로입니다.

v0.26.1은 릴리스 빌드의 자동 확인에서 멈춰 배포되지 않았습니다(쓰이지 않는 파일 하나가 RHEL 8 기준에 걸렸습니다). 이 버전이 그
내용을 그대로 담습니다.

### 고친 것 — Red Hat에서 Linux 판이 시작하지 못하던 것

- **`symbol lookup error: … undefined symbol: XML_SetHashSalt`로 곧바로 꺼지던 것을 고쳤습니다.** `LD_LIBRARY_PATH`에 오래된
  라이브러리(libexpat)가 있으면 — 설계 도구들이 흔히 그렇게 설정합니다 — 앱이 시스템의 것 대신 그것을 집어 시작하지 못했습니다.
  이제 앱은 자기 라이브러리와 시스템 라이브러리로만 뜹니다.
- **agent와 터미널은 원래의 `LD_LIBRARY_PATH`를 그대로 받습니다.** 앱이 띄우는 claude·opencode, 터미널 칸의 셸, agent가 실행하는
  명령은 사용자가 설정한 값 그대로 돕니다 — 그 값에 기대는 도구가 깨지지 않게.
- **RHEL 8에서도 돕니다.** v0.26.0의 데이터베이스·터미널 모듈은 glibc 2.34(RHEL 9) 이상을 요구해, RHEL 8에서는 위 오류를 넘겨도
  창이 뜨지 않았습니다(`version 'GLIBC_2.29' not found`). 두 모듈을 RHEL 8과 같은 환경에서 빌드하도록 바꿨습니다. 이제 glibc 2.28
  이상 — RHEL 8 · Debian 10 · Ubuntu 20.04 이상에서 돕니다.
- **RHEL 7은 여전히 안 됩니다.** 앱 엔진(Electron)부터 glibc 2.25 이상을 요구합니다.

RHEL 8과 같은 환경(AlmaLinux 8.10)에서 오래된 libexpat을 `LD_LIBRARY_PATH`에 둔 채 앱을 띄워 확인했습니다 — 창, agent가 도구로
이슈 만들기, 터미널, 한글 표시. 진짜 RHEL 8 장비에서는 아직 돌려 보지 않았습니다. 앞으로는 릴리스를 만들 때마다 이 두 가지(오래된
libexpat이 있어도 뜨는지, glibc 2.28 안에서 도는지)를 자동으로 확인합니다.

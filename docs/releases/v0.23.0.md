## 이번 버전에서 바뀐 것 (v0.22.0 → v0.23.0)

데이터베이스 마이그레이션은 없습니다.

### 새 기능

- **코드 칸 — 파일.** 창 맨 위 제목 줄의 오른쪽, 최소화·최대화·닫기 바로 왼쪽에 아이콘이 생겼습니다. 폴더 아이콘(`파일`)을
  누르면 창 오른쪽 끝에 위아래 전체 높이로 코드 칸이 열립니다. 대상은 도크에서 보고 있는 대화의 repo(새 대화면 작업 디렉토리
  알약의 repo)입니다.
  - 파일 트리에서 파일을 골라 읽고, 몇 줄 고쳐 Ctrl+S로 저장합니다. 구문 강조와 찾기가 됩니다.
  - 연 뒤에 디스크의 파일이 바뀌었으면(agent가 고쳤으면) 덮어쓰지 않고 알립니다 — 디스크 내용을 불러오거나 내 것으로
    덮어쓸 수 있습니다. 고친 것이 없으면 칸이 디스크를 따라갑니다.
  - 파일의 줄바꿈(CRLF)과 BOM은 저장해도 그대로입니다.
  - 대화의 `자세히`에서 편집한 파일 줄 오른쪽의 `코드 칸에서 열기`가 그 파일을 고친 줄에서 엽니다.
  - 저장하지 않은 고침이 있는 채로 앱을 닫으면 저장할지 묻습니다.
  - 칸과 본문 사이 경계를 끌어 폭을 바꿉니다. 도크를 접어도 칸은 남습니다.
- **코드 칸 — 터미널.** 제목 줄의 `>_` 아이콘(`터미널`)을 누르면 같은 칸이 그 repo의 셸이 됩니다. `pnpm test`, `git status`
  같은 명령을 앱 안에서 칩니다.
  - 셸은 repo마다 하나입니다. 칸을 닫거나, 다른 repo의 대화로 옮기거나, 인박스에 다녀와도 셸은 계속 돌고, 돌아오면 출력이
    그대로입니다.
  - 칸 머리의 `다시 시작`(두 번 누르기)은 셸과 셸이 띄운 프로세스(dev 서버 등)를 끝내고 새로 띄웁니다.
  - 셸은 기본이 PowerShell 7(없으면 Windows PowerShell)입니다. 설정 › 앱 탭의 `터미널 셸`에서 Git Bash·cmd 등으로 바꿀 수
    있습니다.
- **인박스 보기 모드.** 인박스 위에 `시간순 · workspace별 · 상태별` 보기와 정렬 버튼(`최신 먼저` / `오래된 먼저`)이
  생겼습니다.
  - workspace별은 workspace 아래 repo로 한 번 더 묶고, 상태별은 답변 필요 → 실패 → 중단됨 → 완료·미확인 → 대기 중 취소됨
    순서입니다. 묶음 머리를 누르면 접히고, 접어도 개수와 `답변 필요`가 보입니다.
  - 고른 보기·정렬·접은 묶음은 앱을 다시 켜도 기억합니다. 시간순 카드에는 workspace와 함께 repo 이름도 보입니다.

### 알아 둘 것

- **앱 창의 제목 표시줄이 바뀌었습니다.** OS 제목 표시줄 대신 앱이 그린 줄을 씁니다. 빈 곳을 끌면 창이 움직이고 두 번 누르면
  최대화되는 것은 그대로입니다. 이슈·메모를 새 창으로 연 창은 예전 그대로입니다.
- 코드 칸의 파일은 **git repo에서만** 열립니다. 트리에는 `git ls-files`가 보는 파일만 있고(무시된 파일·`.git` 안은 보이지 않고
  고칠 수도 없습니다), 2 MiB가 넘는 파일·바이너리·UTF-8이 아닌 파일은 열지 않습니다. 터미널은 git이 아니어도 됩니다.
- 앱을 끄면 터미널의 셸과 그 셸이 띄운 프로세스가 모두 끝납니다. 출력은 저장하지 않습니다 — 다시 켜면 새 셸입니다.
- 셸이 프로필을 읽는 동안(conda 등) 친 글자는 셸이 버릴 수 있습니다. 프롬프트가 뜬 뒤에 치세요.
